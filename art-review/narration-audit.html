Narration Audit — every line, tagged, with proposed wording (NARR-01)

Every narration surface in the game — the EVENT_NARRATION table (src/ui/util.js) AND every hand-written flash() call in src/ui/flow.js, src/orchestrator.js and src/ui/util.js — rendered exactly as it appears on your screen (seat colors, icons, ingredient art), grouped by moment. Every card carries a keep / cut / merge / rewrite recommendation you can change, plus a notes field. The recommendation is biased toward rewriting, not deleting: this pass keeps roughly the same number of lines and instead proposes distinct verbs/imagery for the handful of moments that currently blur together (flagged below) — it never defaults to a one-line-per-moment cut, and nothing is pre-selected for deletion on your behalf. Where two call sites render byte-identical text, both are listed and flagged as a merge candidate rather than silently collapsed — they're two places in the code that can drift apart. A surface that deliberately renders no text at all is still listed, marked "silent", rather than dropped for having nothing to show.

How this page is built: table cards call the real EVENT_NARRATION builders (via describeFor/narrationVariants) with a fabricated event — the exact same code that ships, so there is zero drift between this page and the game. The three new NARR-02 builders (brokeSailLine/brokeAnchorLine/ stormIntroClause) are called the same way, imported directly from src/ui/flow.js. The remaining hand-written flash() lines can't be called as isolated functions — each ad-hoc card reconstructs its wording using the SAME real name/color/icon helpers (pn/poss/ilabelImg/ DIRNAME) the source line itself calls, and a "Raw source" disclosure on every ad-hoc card shows the exact JS text the extraction script pulled from the file, so you can cross-check the reconstruction against the real code yourself.

End-of-voyage lines: tagged keep with no wording changes proposed this phase — Phase 16's UI-07 owns that box's visibility, not its wording, so any change there is your call to make at that gate, not something to decide here.

This page imports live ES modules and must be served over HTTP (npm start) — opening it directly from a bare filesystem path will fail silently in every current browser, since module imports are blocked from that origin.
