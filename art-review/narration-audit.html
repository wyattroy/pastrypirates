Narration Audit — flow chart, every branch (NARR-01)

Every narration surface in the game — the EVENT_NARRATION table (src/ui/util.js) AND every hand-written flash() call in src/ui/flow.js, src/orchestrator.js and src/ui/util.js — laid out as a flow chart in the order a real game actually plays it: turn start → storm legs → sail → the action you choose → shot clock → round roll-over → voyage end, looping back into the next round. Every branch a builder can produce is its own editable card — every got/heads/reason/ok/winner/ ingredient-present value and every config-gated variant (the trade-cooperation bonus, the sardine/candycrab rule) gets its own card, grouped inside the moment it belongs to. A moment with more than one outcome is drawn as a fork — several cards inside one box. Each card still carries a keep/cut/merge/rewrite recommendation, a notes field, and persists to your browser (localStorage); the toolbar exports every disposition as JSON.

How this page is built: every card calls the REAL builder — the EVENT_NARRATION table via describeFor/narrationVariants, and the real brokeSailLine/brokeAnchorLine/stormIntroClause — with a fabricated event tuned to that specific branch, so every rendering is the exact code that ships. Every card's HTML also runs through the real emojify(), matching what the shipped panel shows. Hand-written flash() lines that can't be called in isolation reconstruct their wording using the SAME real name/color/icon helpers the source line itself calls; a "Raw source" disclosure on every such card shows the exact JS text the extraction script pulled from the file, for cross-checking.

Flow chart edges are derived from the real call paths in src/ui/flow.js (humanTurn → windLeg legs 1/2 → per-square outcomes → humanAct → its outcomes → shot clock → round roll-over → finish/ bakeoff/end) — never invented. Where reachability genuinely depends on game state that can't be shown structurally (e.g. side-bet settlement only fires when spectating captains remain), the edge is drawn dashed and labelled uncertain.

Your pass-1 marks are pre-filled. Every card whose id exactly matches a line you already reviewed carries your tag and notes exactly as you left them — you do not need to redo those. New sibling branches split out of a line you already marked (e.g. dock's other 3 outcomes) start pre-filled from that SAME mark as a starting point, tagged from pass 1 — review and adjust per branch as needed; brand-new branches (like the candycrab line) start blank.

This page imports live ES modules and must be served over HTTP (npm start) — opening it directly from a bare filesystem path will fail silently in every current browser, since module imports are blocked from that origin.
