## Critical Anti-Patterns

| # | Anti-pattern | severity |
|---|---|---|
| 1 | Bumping `PP4_STAMP` before plan 02-07 | blocking |
| 2 | Driving a voyage to its END during a probe | blocking |
| 3 | Editing `4/src/main.js` — the tab-hide gate is verify-only | blocking |
| 4 | Relative paths, or editing the repo-root game | blocking |
| 5 | Returning with a headless Chrome or local server still running | blocking |

**1 — `PP4_STAMP`.** Wyatt chose **ONE DROP** on 2026-08-19: everything lands together and he plays
one real voyage, which is the phase gate. The stamp is the only signal he has that work arrived —
there is no build step, so a stamp bumped early with a half-finished game behind it burns the signal.
It bumps exactly once, in 02-07. 02-07's `must_haves.prohibitions` already carries this.

**2 — `gamelogs/` is append-only.** `writeGameLog()` (`4/src/orchestrator.js:710`) fires on any voyage
that reaches its end, whenever `appState.db` exists and `appState.replaying` is false. It is **not**
hostname-gated the way `usageOn()` is, so a localhost probe writes a permanent row into the shelf
Wyatt reads to understand real play — and the database rules forbid deleting it. Four test rows are
already stuck there from 02-01. `rooms/<CODE>` deletion works perfectly; clean those up as normal.
**02-06 legitimately needs a full voyage** (criterion 2) — that one is expected and should be tagged
with an obviously-attributable `pp_id` so Wyatt can filter it forever. Every other plan: stop short.

**3 — the tab-hide gate (D-05).** `4/src/main.js:157-163` writes the *shared* `paused` node and is
safe only because it sits behind `ui.soloBotGame()` (`4/src/ui/util.js:1740`). Loosening it is how one
player backgrounding a phone pauses the whole table. Wyatt's ruling is **verify, do not change** —
02-03 proved it holds from both sides and left the file byte-identical. Keep it that way.

**4 — absolute paths.** This repo has several trees with an identical internal layout (`4/`, the repo
root, `v2/`, `v2bakeoff/`). A relative path resolves in the wrong one, applies cleanly, passes
`node --check`, and modifies the wrong copy — **every safety signal reports success.** The repo root
is the LIVE game real players are on. After each batch: `git diff --name-only` must show nothing
outside `4/` and `.planning/`.

**5 — kill your browsers.** This phase runs more of them than any other in the milestone. Counted
loops only, never `while(true)`. `pkill -f remote-debugging-port; pkill -f http.server` before you
reply. Wyatt is at the keyboard on the machine they heat.

## What we learned that no document predicted — these belong in `02-FINDINGS.md`

1. **The networked ribbon never built at all.** Before 02-03, a leftover guard from the solo-only
   period silently blocked the entire top ribbon (day counter, boats, clock, skip) in a networked
   game. Found only by trying to test the skip button and discovering there was nothing to test it
   in. Fixed in one line. **02-05 puts the 💬 chip in that ribbon — verify against today's code, not
   any document written before this fix.**

2. **FIX-03's third site is already closed, and the naive fix would have been destructive.** Both
   CONTEXT.md and RESEARCH.md say `esc()` exists in `4/src/ui/util.js`. It does not — what is there is
   a function-local arrow inside `voyageAground()`. The only exported escaper is **`escHtml`**
   (`4/src/ui/recipe.js:24`), and `pname()` already routes typed names through it. Measured on a live
   guest's DOM with an attack-shaped name: renders as harmless text. Escaping `p.msg` wholesale would
   have turned the coin image, ingredient chips, the bolded captain name and the `nobrk` span into
   visible angle brackets in every prompt on both sides.

3. **The typed-name box accepts 40 characters; the database caps at 18. Going over freezes the game
   with no visible error.** Player-reachable. Not in scope for this phase — record it.

4. **`window.onerror` lies here.** The repo's plain dev server sends no CORS headers, so a real throw
   surfaces as a generic "Script error." Use CDP `Runtime.exceptionThrown` to see the actual error.

5. **The sparse-draft crash shape in the plan was wrong.** "Seat 0 and seat 2 picked, seat 1 hasn't"
   does *not* reproduce — Firebase pads that gap with `null` and returns a dense array. The real
   trigger is a lone pick at seat index ≥2 of 4. Found by measuring before building.

6. **`remotePrompt` has no timeout and is deliberately NOT fixed.** Wyatt, 2026-08-19: *write it down,
   don't fix it.* A countdown clock is ruled out by Phase 1's D-03 (the shot clock is not the drop
   handler) and presence detection is Phase 4's MP-13. This is the **headline findings entry**, with
   that reasoning attached so Phase 4 doesn't rediscover it. Also record the source inconsistency:
   REQUIREMENTS.md names three FIX-03 sites, CONTEXT.md lists four under a heading that says three.
