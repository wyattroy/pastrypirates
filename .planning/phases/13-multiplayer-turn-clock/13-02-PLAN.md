<objective>
Deliver CLOCK-01: harden boot against stale/mismatched local session state so a
returning player who last played the pre-refactor build starts clean (clock
running on its own, no timer-toggle workaround) — WITHOUT ever wiping a
legitimately in-progress current-build game, the device identity, or the
remembered timer preference.

Per D-01 this is NOT chasing a live first-turn clock bug (a clean-slate game
already boots fine); it is a targeted stale-state guard. Per D-02 the approach is
a per-blob schema-version stamp checked at boot (RESEARCH Pattern 3), chosen over
a blanket clear precisely because D-02 rates this path costly reversibility.

Purpose: self-resolve, on first load of the patched build, the exact stale-blob
condition that produced the original "stall" for returning players.
Output: two version constants, a v: stamp on the two resumable blobs, and two
boot-time guard checks.
</objective>
