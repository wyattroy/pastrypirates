- **After every task commit:** the quick run, plus that task's own structural assertions.
- **After every code task (each is its own live drop):** the full drill suite, **plus a two-tab crew
  pass AND a solo pass** — solo is the only tier that can see the `db===null` trap.

  end-of-voyage cards on the final live build (Wyatt's ruling, 2026-08-20). This is a distinct gate
  from the per-drop checks and does not substitute for them, nor they for it.
- **Max feedback latency:** ~10s for anything automated; a whole voyage is minutes and is meant to be.

## Wave 0 Requirements

**The gap this file recorded is CLOSED, and the answer is written into `02.15-02` Task 3.**

The open question was: *no automated script asserts that a solo game reaches a prompt and resolves it
with `db===null` and no exception* — the single highest-severity failure mode in the phase
(`netSetPrompt`, `4/src/net/writers.js:71`, is a bare `db.ref(...)` and solo has no `db`).

**Decided:** add it as **assertion 3 of the existing `4/scripts/prompt_field_parity_check.js`** — not
a new script (the research's own don't-hand-roll ruling: extend the gate that exists). It declares
the functions making up the local render-and-resolve path and asserts, **comment-stripped**, that
none of them references a Firebase prompt writer or publisher. Red-proofed with a drill.

**And its limit is stated in the assertion's own header, because a check that overclaims is worse
than none:** a static assertion proves the call is *not written*. It cannot prove a solo game *runs*.
**The runtime proof is a driven whole solo voyage** — every code task exercises one, and Task 6 plays
one end to end. That is what `02.15-01` did informally; this writes it down.

- [x] `4/scripts/prompt_field_parity_check.js` — assertion 3 (the solo guard) + drill · **02.15-02 Task 3**
- [x] `scripts/host_guest_parity_check.js` — `ORCHESTRATION_DECL` row for the pick channel + drill · **02.15-02 Task 1**
- [x] Framework install — **not applicable**, no runner library is used anywhere in this project.
