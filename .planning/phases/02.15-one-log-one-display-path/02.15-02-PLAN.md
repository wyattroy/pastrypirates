<the_shape>
## The shape every conversion in this plan takes. Copy it; do not invent a second one.

**ONE renderer per channel, reached by name from BOTH tiers, taking the answer as an argument.**

- The **renderer** draws and tears down. It knows nothing about Firebase, promises or seats.
- The **local caller** (host's game loop / a pass-and-play seat) wraps it in a Promise and resolves
  that Promise from the answer callback. That is today's `localPickCell`/`localAsk` role, kept.
- The **listener caller** (`watchPrompt`, in `orchestrator.js`) calls the SAME renderer and writes
  the answer to Firebase from the answer callback. **It must name the renderer directly** — if it
  keeps calling a guest-only wrapper, `ORCHESTRATION_DECL` cannot see the convergence and the gate
  would be green on a lie.
- **`appState.currentPrompt`** holds the spec the renderer is currently drawing, set inside the
  renderer and cleared inside its teardown — the "one current prompt" of Wyatt's sentence, in one
  place, on every tier. It has a reader from day one: when a whole game stalls in Task 6, that field
  is the difference between *"an orphaned prompt"* and *"a guess"* (inspect it the way
  `docs/DRIVING-THE-GAME.md` §6 already inspects state).

### THREE HARD CONSTRAINTS. Any one of them broken is a captain who cannot take their turn.

**1. MIRROR WHEN REMOTE — the host's own screen NEVER round-trips through Firebase.**
`runLiveNet()` drives solo and pass-and-play too (the fork at `4/src/orchestrator.js:1839` is
`if(appState.isHost)`, which is **true in solo, where `appState.db` is null**). `netSetPrompt`
(`4/src/net/writers.js:71`) is a bare `db.ref(...)` with no guard and throws on the first prompt of a
solo game. The local branch renders and resolves **unconditionally**; a Firebase write happens only
under the guard `netNarrate` already uses at `4/src/orchestrator.js:308`. **A two-tab test cannot see
this failure — it always has a room.**

**AND THE RULING THAT FOLLOWS FROM IT, TAKEN HERE SO NOBODY RE-ASKS IT:** the research sketched a
`decidePrompt` that publishes a mirror copy of the host's OWN prompt under `db&&room`. **Do not.**
It buys nothing (no guest renders another seat's prompt — `watchPrompt` returns early when
`p.seat!==appState.mySeat`), it makes every guest clear its panel on the host's turn, and it drags
`expireShotClock`'s cleanup condition (`4/src/orchestrator.js:260-283`, currently keyed on
`seatLocal`) into scope, which would leave a stale `prompt` node behind a networked host's own
timeout. **The safe, revertible path is taken and recorded: publish only for a genuinely remote
seat, exactly as today.** This is a decision resolved from the record (D-04's safe stop + tonight's
pure-plumbing constraint), not a checkpoint.

**2. EVERY BRANCH KEEPS RETURNING A PLAIN PROMISE.** `withShotClock()` (`4/src/ui/util.js:1949`) is
channel-agnostic only because it cares that `base` is *a* Promise. Resolve through anything else —
an emitter, a callback registry — and the clock still counts down visibly while **nothing
force-resolves at zero**. Silent, and it is the 30-second auto-skip every player relies on.

**3. `decisionIsLocal(seat)`, NEVER `isHost` and NEVER `seatLocal`.** `decisionIsLocal`
(`4/src/ui/util.js:1804`) is true for **any** human seat at a pass-and-play table. `pickCell` and
`ask` both already use it correctly — this is confirmation, not a change. Do not "simplify" it.

### And the fourth thing, which is not a crash but is how this class of bug survives

**Name where each fork's promise is CREATED, RESOLVED and REJECTED, and verify all three on all
three tiers.** Today the pick channel creates its promise in `localPickCell` (local) or
`remotePrompt` (remote); resolves it on a square click, on `#apStay`, or from
`appState.shotClockForce` at 30s; and **has no reject path at all** — a dropped prompt does not
throw, it simply never settles, and the game loop waits forever behind a board that looks fine.
**That is the failure mode. A converged renderer must not add a second way to reach it.**
</the_shape>
