<objective>
**Group A — ONE DIRECTOR.** The second of six drops (D-01), and the only architectural change in the
phase.

**The premise this plan was first written against was too small, and it has been replaced.** D-06
named two narration call sites; that was correctly traced and far too narrow. **D-24 is the root
cause: there are TWO DIRECTORS.** At `4/src/orchestrator.js:1654-1655` the host's screen is driven
by the game loop — `runLiveNet()` plays the voyage and calls the renderers directly as it goes —
while a guest's screen is driven by **nine independent Firebase listeners**, each deciding on its own
what to draw and when. **The renderers are shared, which is why 02.1's state-layer fix helped and why
this was missed. The orchestration is not.** Every renderer has two independent sets of callers that
can drift, and have.

**That is the "two parallel code paths" of item 18.** D-06 and D-07 are **superseded by D-25, not
withdrawn** — the narration divergence is one instance of the general fault, and it is still fixed
here.

**Wyatt's pick, verbatim, told plainly that it was bigger and riskier and touched the host path that
works for him today: "do it properly" (D-25).** The host becomes a listener to its own broadcast: it
computes the game and publishes, then draws from that same stream exactly as a guest does. **The
precedent is one line below the fork** — `watchChat()` is called by every client including the host,
and cannot drift. It is a worked example in the same file, not a theory.

**How closely the game display can follow `watchChat`, answered honestly** — this is the question the
plan owes, and the answer shapes the staging:

- **Display-only channels can follow it exactly.** Narration, board, camera, ribbon, battle stage,
  turn order: the host feeds them and draws from them, nothing travels back. This is chat's shape,
  one-way, and it carries **seven of Wyatt's eight divergences**.
- **Input-carrying channels cannot follow it as-is.** Chat is fire-and-forget; a prompt is not. The
  host's loop **awaits an answer** — `ask()` at `4/src/ui/util.js:1555` forks to `localAsk` for its
  own seat and to `remotePrompt` for a remote one, and `remotePrompt` returns a promise that
  `sendResponse` resolves over Firebase. Making the host answer its own prompt through that round
  trip is a real change with real risk, and it carries **one** divergence.
- **And the transport cannot be Firebase for the host's own screen.** `runLiveNet()` drives **solo
  and pass-and-play as well as a networked host** (the fork is `if(appState.isHost)`, which is true
  in solo, where there is no room). `netSetPrompt` dereferences `db` with no null guard
  (`4/src/net/writers.js:71`). **A host that drew only from its own Firebase echo would take solo and
  pass-and-play down.** Chat gets away with it because chat is switched off entirely in solo
  (`4/src/orchestrator.js:1645`). The game display cannot be.

**So "one director" here means one local dispatch that both tiers draw from, with Firebase as the
transport for remote clients only** — the host feeds the dispatch directly and mirrors to Firebase
when `db && room`, exactly as today's `isHost && db && room` guards already do; a guest feeds the
same dispatch from its listeners. One place anything is drawn from; no round trip on the host's own
screen; solo unaffected. That is faithful to D-25 and survives contact with solo.

Purpose: drift becomes structurally impossible instead of kept away by discipline.
Output: one draw path, seven divergences closed at the safe stop, and an honest list of what is left.

**D-04 is the stated exit condition, not a note.** If this balloons: **land what is safe, write down
exactly what is left, and move to Group B.** Wyatt's ruling. The staging below exists so that
stopping is always possible at a clean line, and **Task 7 runs whether or not Stage 4 was attempted.**

**D-05 still stands and still protects this work: do NOT delete the `isHost` branches.** They decide
who broadcasts and who creates the room, and that is the project's own sanctioned residue. **The fork
at `:1654` is being restructured, not deleted — the host still computes the game.**

**Determinism: no engine change.** Nothing in this plan alters what `4/src/engine/index.js` emits.
Plan 04 owns the one sanctioned engine change in this phase; **a second one is a re-scope, not a
detail.** If a stage appears to need one, stop that stage and write it down.
</objective>
