## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug, found during Task 3's measurement] `enterCenterStage()` was a second, unguarded site for the same item-11 popup-timing bug**
- **Found during:** Task 3, re-measuring after the first fix (promptTick's `want` gate alone) still showed 15 violations
- **Issue:** `promptTick()` returns early into `enterCenterStage()` for any stage-flagged prompt (ceremony cards, the bake-off), which set `box.style.display="flex"` unconditionally — completely bypassing the `want`/`pendingReveal` gate just added one function away.
- **Fix:** Same `pendingReveal` check, applied inside `enterCenterStage()` itself, re-evaluated on every call.
- **Files modified:** `4/src/ui/stage.js`
- **Verification:** violation sampler dropped from 15 to 0 across an identical driven session.
- **Committed in:** `5b1af61`

**2. [Rule 1 — Bug, found during Task 4's measurement] Item 22's transform trick did not reach three raw `vw`/`vh` sizings**
- **Found during:** Task 4, the first live desktop screenshot — the captains panel was correctly capped but the ribbon and board still spanned the full 1400px viewport.
- **Issue:** CSS `vw`/`vh` units are tied to the true viewport regardless of any transformed ancestor; `body.pp4Stage #boardwrap`'s `width:100vw;height:100vh`, `#pp4Prompt.radial`'s `height:100vh`, `#pp4Prompt.pp4Center`'s `width:100vw`, and one inline `box.style.width="100vw"` in stage.js all bypassed the containing-block trick entirely.
- **Fix:** Converted to `%` (or removed in favour of `inset:0`'s own auto-fill, for `#boardwrap`), which resolves against whatever containing block is actually in force.
- **Files modified:** `4/index.html`, `4/src/ui/stage.js`
- **Verification:** re-screenshotted at 1400px/1920px/390px — full stage now correctly capped/centred on desktop, phone unchanged.
- **Committed in:** `94adceb`

**3. [Rule 1 — Bug, found during Task 4's first implementation] `body`'s own box collapsed to ~56px tall once capped**
- **Found during:** Task 4, first live diagnostic read of `document.body.getBoundingClientRect()` at 1400px
- **Issue:** `body` holds no in-flow content once the stage is up (everything inside it is `position:fixed`, taken out of flow), so its own block-box height collapsed to whatever tiny non-fixed content remained — and `vhPx()`'s new branch would have handed every height-dependent calculation on the page a ~56px "screen".
- **Fix:** Added `min-height:100vh` to the same `body.pp4Stage` media-query rule.
- **Files modified:** `4/index.html`
- **Verification:** `bodyRect.height` confirmed 900/1080 (matching the true viewport) at desktop widths after the fix.
- **Committed in:** `94adceb`

**Total deviations:** 3 auto-fixed (Rule 1 — all bugs found and fixed during this plan's own measurement passes, before being handed to Wyatt).
**Impact on plan:** None of the three changed which items were in scope; all three were necessary to make Task 3's and Task 4's stated goals actually true rather than partially true.
