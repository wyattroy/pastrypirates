**2. [Rule 6/measurement, not an auto-fix — flagged, not fixed] Item 10's ceiling change measured to be a no-op**
- **Found during:** Task 6's two-tab QA pass, while satisfying the overnight run's explicit instruction to measure a long narration line's hold "the number, not an impression"
- **Issue:** `4/src/ui/stage.js`'s outer clamp (`Math.max(2550, Math.min(8775, msgHoldMs(msg)*1.5))`) can never bind at 8775 (or the old 6750) because `msgHoldMs()` itself — imported unchanged from `4/src/ui/util.js` — caps its own return value at `HOLD_CEILING_MS = 2000` before the `*1.5` multiplier is even applied. `2000 × 1.5 = 3000`, always below both the old and new outer ceiling. So changing `6750` to `8775` is a correct, literal, harmless edit that currently has **zero effect on anything a player sees**.
- **Live measurement, not theory:** instrumented both host and guest with a `MutationObserver` on `.pp4Bub` add/remove during a real driven 22-second crew-game window. Longest bubble observed on **both** sides was the storm narration line, holding **3305ms (host) / 3304ms (guest)** — matching `3000ms` (the ceiling-capped `msgHoldMs(msg)*1.5`) plus the fixed ~300ms fade-out tail in `finish()`, to within 1ms of each other. This also positively confirms the shared scheduler produces identical holds on both tiers (no host/guest drift here), which was the other half of the overnight rule's requirement.
- **Not auto-fixed, because the real lever is a different constant (`HOLD_CEILING_MS`) in a different file (`util.js`) than the one D-10 named, and raising it affects every hold computation in the game, not just the "long line" case D-10 targeted** — Rule 4 territory (ask about the broader change), not something this overnight run should decide alone. D-10's literal instruction ("do not touch the floor unless he says so") was honored to the letter; the finding is that the letter of the instruction doesn't reach the thing he actually complained about.
- **Files modified:** `4/src/ui/stage.js` (the literal, harmless edit — kept)
- **Recommendation for Wyatt:** if the long-narration complaint is still live, the number that actually needs raising is `HOLD_CEILING_MS` in `4/src/ui/util.js:1220` (currently 2000), not the number D-10 named.

## Issues Encountered

- `4/scripts/*.js` uses ES module `import`, not CommonJS `require` — the root `package.json` has `"type": "module"`. First draft of `audio_map_check.js` used `require()` and failed; converted to `import`/`fileURLToPath` matching every other script in the directory.
- Headless Chrome's `--headless --screenshot --window-size=390,844` CLI flags do NOT reliably set the layout viewport — measured at a fixed `innerWidth=500` regardless of the requested size, in both classic headless and `--headless=new`. Switched to the CDP `Emulation.setDeviceMetricsOverride` approach the project's own `4/scripts/mp_rig.mjs` already uses, which is accurate and is the pattern any future screenshot tooling in this repo should copy rather than re-discovering this.
- `notes/` is gitignored repo-wide (protecting Wyatt's private playtest notes and scratch files), which initially blocked `git add` on the sketch files entirely. Resolved with `git add -f` scoped to just the two sketch folders rather than editing `.gitignore`.
