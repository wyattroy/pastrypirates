# Phase 02.2 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Source: `02.2-RESEARCH.md` § Validation Architecture.

> ## ⚠️ READ THIS BEFORE TRUSTING ANY GREEN RESULT IN THIS PHASE
>
> **A green suite proves nothing about what Wyatt will see.** This phase's faults are almost all
> things that are *drawn* — a duplicated bubble, a camera aimed at the wrong boat, a prompt that
> falls back to a flat card. **Not one of them is visible to an assertion over game state.**
>
> That is not a theory. On 2026-08-19 a headless shakeout blessed a build by checking ship
> positions, turn order, event indices and dubloon counts — every one of those checks passed
> honestly — and Wyatt then found **seven faults in twenty minutes**, all visible on the first
> screen. *"The checks were not wrong. They were measuring a different thing than the one that was
> broken."*
>
> **So: the screenshot is the instrument here, and the automated gates are the seatbelt.** Every
> plan requires a picture of the rendered page, on **both** sides of a two-tab crew game, before
> anything is handed over (D-03).

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Hand-rolled Node scripts. No test runner, no library — each script exits 0 or 1. |
| **Config file** | None. Root `package.json`'s `test` script is a chained `&&` of `scripts/*.js`. |
| **Quick run command** | `node 4/scripts/no_undef_check.js && node 4/scripts/stage_import_check.js` |
| **Full suite command** | The ten `4/scripts/*.js` gates by name, **plus** a live two-tab crew game screenshotted on both sides |
| **Estimated runtime** | Gates ~5s. The two-tab pass is minutes and is **not optional**. |

### The trap this phase must not fall into

**Root `npm test` runs 21 gates and NOT ONE of them loads `4/`.** They scan the v1 game at the repo
root — a different game that real players are on. `scripts/host_guest_parity_check.js` is the sharpest
example: it is named for exactly this phase's problem and **it has never looked at `4/`**.

**Therefore: root `npm test` is not evidence about anything in this phase.** Run the `4/`-side gates
**by name**. Wiring them into `npm test` is Phase 3 (TEST-06), not this phase.

Existing `4/` gates: `stage_import_check.js`, `no_undef_check.js`, `pp4_timeroff_check.js`,
`pass_coin_test.js`, `pass_narration_test.js`, `planner_singleton_check.js`, `dlog_quantity_check.js`,
`prompt_field_parity_check.js`, `seat_arg_check.js`, `trade_offer_measure.js`.

## Sampling Rate

- **After every task commit:** the quick run command above, plus any gate the task itself added.
- **After every plan (= every drop):** the full `4/` gate set **and** the two-tab screenshot pass.
- **Before the phase gate:** Wyatt plays a crew game. That is the gate; nothing below replaces it.
- **Max feedback latency:** ~5 seconds for the gates. The screenshot pass is deliberately slower —
  it is the only instrument that can see what he sees.

## Wave 0 Requirements

Three new scripts, each **required by a success criterion** rather than chosen — and each **written
red first**, proven to fail against the current tree before its fix lands. A check nobody has seen
fail is not protection; this project has had three separate checks measure something other than what
they named, in a single night.

- [ ] `4/scripts/audio_map_check.js` — asserts no key appears twice in the sound map. `docs/AUDIO.md`
      asks for this assertion by name. Must exit **1** against today's `4/src/ui/audio.js`, which
      lists `anchorHold` at both `:94` and `:118`.
- [ ] `4/scripts/bot_bake_pass_check.js` — proves from the event stream that no bot both passes and
      bakes in one turn. The roadmap's success criterion says *"proven from an event stream"*, so a
      check is the deliverable, not an extra.
- [ ] `scripts/economy_table.js` — produces PAR-12's table (purses over time, battle counts, voyage
      length) across today's settings and each of Wyatt's candidates. A **report generator**, so
      "red first" takes the form of reconciling its baseline row against `bot_ladder4.js`'s already
      published figures before any new row is believed.

**No other tooling is planned.** CLAUDE.md rule 7 — the ask is to fix the game.

## Reproduction tasks are not tests

Five items are **CANDIDATE** — reported once, not yet reproduced: **2, 3, 11, 14 (the ordering
half), 15/20**. Their plans open with a reproduce-first task whose acceptance criterion is an
**observation and a screenshot**, and whose fix task is blocked on it.

**An OBSERVED / NOT-OBSERVED verdict is a legitimate output.** *Not reproduced* is a real result and
must be recorded as one — **not** quietly upgraded into a fix. Four of five defects reported at the
02.1 gate turned out not to exist, and the cost of believing them was two days.
