## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug, found during Task 2's own matrix run] `Math.max(...purseSamples)` crashed every 300-game run, silently**
- **Found during:** Task 2, the first attempt at running all four matrix cells at 300 games each. Every cell produced a 0-byte `.json` file despite the shell reporting a plausible wall-clock time and no visible error in the truncated bash output.
- **Issue:** `worstPurseEverHeld: purseSamples.length ? Math.max(...purseSamples) : null` spreads the entire purse-samples array (thousands of entries at 300 games × 4 seats × ~15 turns each) into a single function call. V8 has a hard argument-count ceiling for spread calls; past roughly 150 games the array crossed it and the process threw `RangeError: Maximum call stack size exceeded` and exited — after all the expensive simulation work had already run, but before the one `console.log` that would have written the JSON. Confirmed directly: `node scripts/economy_table.js 200 7919 --json` reproduced the exact `RangeError` at that stack trace line.
- **Fix:** Track a running `worstPurseEverHeld` variable, updated inside the same loop that already pushes each sample — no second pass over the array, no spread. `median()`'s own `[...arr].sort(...)` was checked and is safe (array copy, not a function-argument spread) and was left unchanged.
- **Files modified:** `scripts/economy_table.js`
- **Verification:** `node scripts/economy_table.js 200 7919 --json` — succeeds, correct file size, no error. Re-ran the 100-game red-proof against `bot_ladder4.js` after the fix — 14.77 mean rounds, 0 unfinished, matching exactly, same as the pre-fix red-proof. Re-ran all four 300-game matrix cells — all four succeeded, all four `harnessControls` sets held, all four reported 0 unfinished voyages.
- **Committed in:** `3aea857` (part of Task 2's commit — caught and fixed before the matrix was trusted or the report written, not a follow-up)
