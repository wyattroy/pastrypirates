## THE CONVERGENCE ANSWER — required before a line is written (rule 23 / DISPLAY-RULES §1)

> **What makes the baker's screen and a spectator's screen agree?**

**They are the same function reading the same object.** Not two paths kept in step.

`playBakeoffLive` is already **fully data-driven**: `setup.before`, `setup.swaps`, `bake.locked` and
`bake.order` determine every frame of the cover sweep, every swap arc and every reveal. The baker
and the spectator are handed the **same spec** and run the **same choreography** from it. The only
difference is the **response mechanism** — the baker's crates take taps, the spectator's do not.

This is `pickCell()`'s tracer pattern applied verbatim (`4/src/ui/flow.js:625-631`): *one spec, built
once, handed to both branches — the local render and the remote wire payload cannot drift apart
because they are literally the same object.* Copy that comment's discipline as well as its shape.

**The trap, named so it is refused:** the cheapest-looking build is *"the host already animates the
bench; I will add a listener that draws a snapshot for the guest."* **That is the second director**
(`4/src/orchestrator.js:1654`) and it is exactly how seven divergences got built. **When a second
consumer appears, CONVERGE — make the first go through the new path too.**

**Do NOT add a tenth Firebase listener.** `watchBattle` already exists, is already in the parity
gate's `LISTENERS` array, and already carries a live many-writes-per-event stage. Reuse it.

**Do not re-introduce privacy.** Wyatt reversed that on 2026-08-18 (REQUIREMENTS.md Out of Scope).
Face-down for everyone, baker included — the watcher sees the same puzzle and can be wrong too.

## THE DETERMINISM DOOR — this plan does not go through it

Phase 3 deliberately left the corpus uncaptured *for this phase* (`03-01-PLAN.md`: *"the one-way door
is still open for Phases 4 and 5"*). **This plan does not need it and must not use it.**

**Every change here is UI/orchestration tier.** The engine's `bakeSetup`/`bakeResolve`/`bakeRewatch`
are called in the same order, with the same arguments, drawing the same random numbers, whether the
captain answering is local or remote. `bakeTurnLive` (`4/src/orchestrator.js:955`) already computes
`setup` **before** it looks at who is playing, and that ordering is load-bearing — leave it exactly
where it is.

**If you find yourself about to change what the engine emits, STOP and report it instead.** Say why a
UI-tier fix cannot do it. CLAUDE.md prefers UI-tier, and going through that door costs Phase 3's
whole safety net.

## ABANDONMENT ORDER — this run may not finish, and that is planned for

Tasks are ordered so that stopping early always leaves the game **safe**, never half-safe:

| Stop after | What Wyatt gets | What is still broken |
|---|---|---|
| Task 1 | Nothing shipped — an answer to a question that has been open since 2026-08-08 | Everything |
| Task 2 | **A guest bakes on their own screen** (MP-04, MP-06) | Spectators still see the waiting note; clock unchanged |
| Task 3 | **+ every captain watches the bake** (MP-05) | Clock unchanged |
| Task 4 | + no clock, disconnect-safe (MP-13) | — |

**Task 4 is last on purpose.** Until it runs, the existing shot clock is still the safety net for an
absent captain — so an abandoned run cannot strand the table. **Removing the clock before the
disconnect fallback exists would make the game worse, so those two halves ship in one task or
neither.**
