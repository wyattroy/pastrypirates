**Plan 01's state fix was necessary but not sufficient.** On the live guest, `windNow` read `"S"` and
`windNext` read `"W"` — the data is there, correct, exactly as Plan 01 proved. **And the wind pill was

## Task 4 — the phase gate. He played, and it did not hold together.

Two separate turn-blocking defects, one on each side of the table.

### Defect A — a guest never sees a prompt that was already outstanding when it loaded

**Mechanism pinned in code, not guessed.** `watchPrompt()` in `4/src/orchestrator.js` bails with:

```js
if (!p || p.seat !== appState.mySeat) { panel(""); ... return; }
```

On a fresh load that callback fires **before `appState.mySeat` is assigned**, so the outstanding
prompt is discarded. Firebase only re-fires a listener on *change* — so the prompt is never offered
again, and the guest simply sits there.

**Observed live:** the prompt for seat 1 (`q2_1787195977632`, *"What do ye WANT from the table?"*) sat
in `rooms/BVUR/prompt` while the guest showed **no message, no buttons, no sail cells**. The host
waited indefinitely on a captain who had never actually been asked. **Proven** by calling
`watchPrompt()` again once `mySeat` was set — prompts rendered immediately and the guest played its
queued turn (Crystal Sugar / coins only / Offer it!).

**With the turn clock off there is nothing to break the deadlock.** The table stops.

### Defect B — the host does not see an incoming trade offer until it refreshes

Wyatt made this call explicitly: the offer only appeared **after he refreshed**.

**Rule out the hidden-tab explanation, and it is ruled out on his testimony, not on a guess.** He was
in the Claude Mac app with the game visible beside it, and stated the game was continuing without
pausing — so `DRIVING-THE-GAME.md` §8b's background-tab throttling does not apply here.

**Mechanism NOT established. The following is a candidate only and must not be read as a diagnosis:**
`flow.js:186`'s `if (pre) return pre.then(() => localAsk(...))` chains a prompt behind a prior beat, so
a beat that never resolves would leave the prompt undrawn while the board carries on regardless.
`TRADE-SYSTEM.md` I1 says a hail interrupts the **whole table**, so the host was supposed to be asked.
