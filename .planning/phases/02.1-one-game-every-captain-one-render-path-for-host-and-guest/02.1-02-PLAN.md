<objective>
Stop `emojify()` from reading inside HTML attribute values. `panel()` runs the whole assembled button
row — including every `data-why="..."` attribute — through `emojify()`, which is a blind string
replace with no idea it is inside an attribute. When a why-sentence contains a coin (🌕), the
substitution splices `<img class="narrIcon" ...>` — three literal double-quotes — into the middle of
an already-correctly-escaped attribute value, closing it early and corrupting the button's markup.
That corrupted markup measures well past the 16-character radial cutoff, which is why the whole prompt
falls back to a flat card. This hits host and guest alike, because `panel()` is the one render sink
both paths call into.

Purpose: this is the second named bug in Wyatt's scope for this phase, independent of the state-layer
fix in Plan 01 — it is caused by a different mechanism (attribute-blind string substitution, not stale
state) and touches a different file. Fixing `emojify()` once protects every current and future
`data-*` attribute this codebase builds, not just `data-why`.

Output: an attribute-aware `emojify()`, red-proofed against a synthetic why-string containing a coin,
and a live browser screenshot showing the previously-flat prompt bloom correctly on both host and
guest.
</objective>

    untouched — `emojify()`'s contract (takes an HTML string, returns an HTML string with emoji
