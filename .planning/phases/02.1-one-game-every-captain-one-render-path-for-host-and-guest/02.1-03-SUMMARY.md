# Phase 02.1 Plan 03: One Button Row, Built In One Place — Summary

**Seven fields had drifted between the host's prompt and the guest's copy of it, and every one was
caught separately, by a person looking at two browser windows. There is now one function that builds
the row, the seventh field is on the wire, and an eighth cannot go missing quietly.**

## Performance

- **Duration:** ~30 min
- **Tasks:** 3 of 3
- **Files changed:** 3 modified, 1 created — all under `4/`
- **Commits:** `757ba1e` (the builder), `75dc788` (the gate)

## What was actually wrong

`ask()` composes a prompt once, on the host. If the seat that has to answer is not the host's own,
it **flattens** the option list onto the wire — six parallel arrays and a handful of flags — and the
guest's `watchPrompt()` rebuilds a button row from them. Those were two pieces of code that had to
agree, and nothing made them. The orchestrator's own comment said so:

> *"This renderer is a genuine second copy (host and guest render prompts from different sources), so
> a change to one that skips the other reintroduces the bug on whichever side was forgotten."*

That comment was right seven times:

| Field | What a player saw when it was missing |
|---|---|
| `disabled` | a greyed option arrived **ungreyed** on the guest — a dead circle you could click |
| `why` | the greying crossed, the **reason** did not; tapping the greyed circle said nothing |
| `back` | the "‹" escape hatch was host-only — a guest had no way back out of a decision |
| `flipIdx` | a remote player got a stray **"FLIP!"** button sitting in the panel |
| `stage` | host: the dimmed 420px centre-stage card. Guest: a small pill. *"the narration box stage doesn't look the same for guest and host"* |
| `shorts` | the guest fell back to a flat card **for the commonest prompt in the game**. *"the guest doesn't have radial action menus"* |
| `seats` | **found by this phase's research, still missing.** A "Call Dough Hook" circle blooms over Dough Hook's boat on the host and around the caller's own boat on the guest |

Not seven accidents — one structural fact producing the same accident seven times. **A field is
cheap to add on one side and invisible to omit on the other.**

## What changed

**`optionButtonsHTML(items)` in `4/src/ui/util.js` is now the only definition of what an option
button is.** `localAsk` (host), `watchPrompt` (guest) and `watchDraftPrompt` (the recipe-draft
channel, a third ~15-line copy of the same markup) all call it. `backButtonHTML(idx)` does the same
for the "‹" button both call sites hand-built identically.

**What is NOT shared, deliberately:** the click wiring. `localAsk` still resolves its own promise
with `res(i)`; `watchPrompt` still writes an answer to Firebase with `sendResponse(p.id,i)`. A local
promise and a network round trip are different things. This is the `sailHighlightRect()` shape
(G25) — one shared builder, each caller keeping its own handler — applied to the button row.

**The seventh field crosses.** `ask()`'s payload gained `seats`. `stage.js:1174`'s anchor logic is
**unchanged**; it simply starts finding a `data-seat` that was never there before. Empty string for
absent (RTDB drops null holes from arrays), and **seat 0 is a real captain**, so both the send and
the read test `!=null` rather than truthiness — the falsy-zero trap this convention walks straight
into if nobody names it.

**One escaper, not three.** The local `esc()` in `flow.js` and `escW()` in `orchestrator.js` are
gone. The builder escapes through `recipe.js`'s `escHtml`, which **also escapes `>`** where neither
of those two ever did. No rendered reason changes: no `why` string in `4/` contains a `>` — checked,
not assumed.

The narration-box reveal rule is untouched. The builder makes only what goes **inside** `.apBtns`,
never the order `panel()` assembles `.apBack → .apMsg → .apBtns → .apSub` around it.

## Red/green, byte-for-byte

The refactor is only allowed to change *nothing* a player sees, so the test is equality against the
code being replaced. `scratchpad/test-optionbuttons-parity.mjs` extracts `optionButtonsHTML` **from
the shipping source on disk** (util.js cannot be imported in node — it starts timers and never
exits) and compares its output to the two template literals as they stood at `HEAD~`, copied in
verbatim as oracles.

- **RED:** `FAIL — not defined in the shipping source: optionButtonsHTML, backButtonHTML`
- **GREEN:** **12 of 12 PASS** — the ordinary fan, disabled+why+colour (against *both* the host and
  the guest oracle, which is the equality that matters), both `Call` options including **seat 0**,
  the draft channel's narrower field set, disabled-with-no-reason, why-without-disabled, the back
  button, and the deliberate `>`-escaping improvement.

## The gate 4/ never had

`4/scripts/prompt_field_parity_check.js`. One assertion, in two parts:

- **(A) the wire.** The key set `ask()`'s payload writes must equal the `p.<name>` set
  `watchPrompt`'s ask branch reads — modulo three allow-listed entries, each carrying its reason
  (`id` and `seat` are stamped by `remotePrompt()`; `battle` rides on the *other* `kind:"ask"`
  payload). Measured on the real tree: **host sends 14, guest reads 16, difference exactly the three
  allow-listed.**
- **(B) the builder.** All three renderers must call `optionButtonsHTML`, defined exactly once.
  Without (B), (A) sails past a re-inlined row — reading every field off the wire does not help if
  the markup is then hand-assembled a second time.

**Red-proofed before it is trusted (project rule: check that a check can FAIL).** Seven synthetic
violations, each applied to a **copy** of the real source under `os.tmpdir()`, never to `src/`:

| Drill | Result |
|---|---|
| 1a `ask()` stops sending `seats`, guest still reads it | FAIL, names `seats` |
| 1b guest stops reading `p.seats`, `ask()` still sends it | FAIL, names `seats` |
| 1c anti-vacuity — no `kind==="ask"` branch at all | FAIL, not a silent pass |
| 1d anti-vacuity — no remote payload at all | FAIL, not a silent pass |
| 1e `localAsk` re-inlines its own row, wire untouched | FAIL (part B) |
| 1f a second `optionButtonsHTML` definition | FAIL |
| 1g `seats:` left only in a **comment** after deletion | FAIL, names `seats` |
| Z negative control — the real `4/` tree | **PASS** |

**1b is the direction all seven real drifts took**, and the one a reviewer cannot see. **1g is why
comments are blanked first** with `seat_arg_check.js`'s quote- and regex-aware stripper rather than
a line-prefix filter: this gate's own header quotes `seats:` and `p.seats` verbatim, and a check
that cannot tell prose from code makes writing the explanation an offence. The drill's surgery
helper **throws if a replacement target is not found**, so a drill whose edit silently missed cannot
report a verdict about nothing.

There is also a **vacuity floor** (8 fields per side) and every locate failure — `ask()`,
`watchPrompt()`, the payload literal, the ask branch, each of the three callers — is a loud FAIL
carrying *"re-anchor this gate rather than deleting the assertion"*, because the cheapest way to
make a gate green is to move what it reads.

## Deviations from Plan

### [Rule 2 — Missing critical functionality] The gate needed a second part

The plan specified one assertion: the wire field sets must match. Built exactly that, it **passes
over a `localAsk` that reads every field and then builds its own row again** — which is the state
this whole plan was undoing, and a must-have truth of it. Part (B) was added (all three renderers
call the builder; it is defined once), and **drill 1e demonstrates the hole it closes**: the wire
untouched, the render forked, part (A) green and part (B) red. One assertion, one PASS/FAIL line,
two sub-checks — the same shape `host_guest_parity_check.js`'s assertion 2 already uses.

### [Rule 1 — Bug, in my own instrument] Assertion 3 failed on a button the builder never built

First full probe run, assertion 3 red on seven rows: `<button class="apBtn" id="apStay" style="…">`.
That is the sail prompt's **"Stay put"** confirm — a hand-built one-off with **no `data-i`** and no
option behind it, created by `localPickCell`/`remotePickHighlights`, not by `optionButtonsHTML`. The
grammar was being applied to something outside its remit. Scoped the check to buttons carrying
`data-i`, and made the instrument **count and print the excluded ones** (`55 non-option #apStay
button(s) excluded by design`) so the exclusion cannot quietly grow to cover a real row.

### [Rule 3 — Blocking] Two harness stalls, neither a game fault

1. **`#btnStart` opens a confirm modal.** *"Set sail? — Everyone's aboard? / Wait, not yet"*
   (`#btnConfirmStart`). It is not an `.apBtn`, so it is invisible to any `#actionPanel` driver. The
   first run sat on it for **200 seconds with an empty act log and zero rows captured**. Assertion 0
   (the anti-vacuity floor) is what turned that into a loud FAIL rather than a green run over
   nothing — assertion 3 "passed" on 0 rows in that same run, which is exactly the vacuous shape
   this project keeps having to catch.
2. **`#boardwrap.offsetParent` is null under its fixed ancestor**, so waiting on it timed out on a
   board that was plainly on screen. Measured the rect instead.

Both scratchpad-only; no repo file changed.

### Nothing architectural

No engine change, no wire-format change beyond the one additive field, no package install, no
determinism question. `watchEvents()` was not touched (02.1-01's function). The quantity slider was
not threaded across the wire (`util.js:1460`'s named exception, Phase 5's MP-08). The draft
channel's wire payload was not widened — only its rendering stopped duplicating the pattern.

## What is proven, and what is not

Stated plainly rather than left implied.

- **The render half of the seat path is proven on a real guest** — assertion 6 built a two-`Call`
  row from the guest page's own loaded `util.js` and got `data-seat="0"` and `data-seat="3"`.
- **The wire half is proven statically**, by drills 1a and 1b, in both directions.
- **The two together, live, are not** — a real "Call {captain}" row needs a battle to occur AND a
  third seat to be spectating it, and this plan is forbidden from forcing one by injecting state
  into a networked client. **No battle occurred naturally in the drive.** The static gate is the
  durable protection for that field; the anchored bloom over a named boat is worth a deliberate look
  at the phase gate, alongside 02.1-01's battle and storm cameras, which are in exactly the same
  position for exactly the same reason.
