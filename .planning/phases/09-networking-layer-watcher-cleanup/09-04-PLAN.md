<objective>
Turn this phase's invariants from things that are currently true into things that stay true.

D-04 does not merely say the registry should be the single attach point — it says that must be mechanically enforced, "not left to discipline", because Phase 10 and Phase 11 touch this same code again and would otherwise quietly reintroduce raw listener calls. Phase 8's own module contract doc makes the same argument about the engine tier in almost the same words. A grep run once during execution and pasted into a summary proves nothing about the next three phases.

There is one deliberate deviation from the Phase 8 precedent. `engine_contract_check.js` strips line comments before matching, and its header explicitly flags that this is safe only because the engine and shared tiers contain no URL literals, asking that the assumption be reconfirmed if one is ever added. `src/net/index.js` carries the Firebase `databaseURL`. This is that reconfirmation moment, and the answer is to not comment-strip at all: match literals and word boundaries directly and accept the occasional false positive inside a comment. That trade is correct because a false positive costs a reworded comment while a false negative silently reopens the bug class this phase exists to close.

Purpose: make SPLIT-04 and NET-02 enforceable rather than aspirational.
Output: `scripts/net_contract_check.js` with five assertions and a demonstrated red path, a wired `npm test`, and an updated module contract doc.
</objective>

**The handler-injection seam.** This is the design decision a future reader is most likely to undo by accident, so explain it as a rule with a reason. The networking module owns transport — building references, attaching and detaching listeners, reading and writing. Every callback body stays in the classic script and is handed to the networking module as a plain function argument. The module therefore executes UI logic indirectly, once removed, through a caller-supplied function, and never through an import. State the direction explicitly: the UI may import networking; networking may never import the UI.

Then state the constraint that makes the seam safe: dispatch is synchronous. The caller's handler runs in the same tick as the raw Firebase callback, with no emitter and no microtask between them. Explain why — a guard flag checked inside a handler could otherwise change value between the Firebase callback firing and the handler running, which would corrupt a replay rebuild with no visible symptom. Name the alternative that was considered and rejected: an event emitter would be technically synchronous too, but it adds an indirection layer with no benefit here, since every watcher has exactly one consumer, and it makes accidental deferral easy to introduce later.

**The two listener scopes.** Document that exactly two exist. Room-scoped listeners are torn down together when a room is left. Session-scoped listeners — the connection and presence watchers — are attached once per page life and must survive a room leave, because they track the browser's connection to Firebase itself rather than any particular room. Say that tearing them down alongside room listeners would be a regression rather than a fix. This is the single most likely well-intentioned mistake a later phase could make here.
