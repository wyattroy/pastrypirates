Migrate nine watchers: the timer flag, the shot clock, chat, battle, the recovery strip, the per-seat draft prompt, the broadcast event feed, the prompt, and narration.

For each one, do exactly two things and nothing else.

**In `src/net/watchers.js`:** add a wrapper following 09-01's shape — preserve the call site's existing guard by returning `null` when the guard would have short-circuited, build the Reference from the same path expression the call site uses today, and return `registry.attach({...})` with a room scope, the event string unchanged, the caller's handler passed as the callback itself, and a short stable label. Derive each label from the path's last segment so the registry listing reads legibly in a browser console.

Three of the nine carry details that are easy to lose:

- Chat and the event feed use the child-added event, not the value event. Carrying the wrong event string would attach a listener that never fires for existing data and, worse, would make the detach call a silent no-op, because the event string must match for removal.
- The draft-prompt watcher builds a per-seat path. The seat is read from the classic script's own state today; pass it in as a parameter rather than reaching for it from inside the module — `src/net/` reads no app state.
- The recovery and shot-clock call sites carry an early-return guard on the database handle and room code; the draft-prompt, event-feed, prompt and narration call sites do not. Preserve each call site's current behaviour exactly rather than normalising them. Adding a guard where none existed is a behaviour change; removing one is a crash.

**In `index.html`:** replace the Firebase listener call with a call to the new wrapper, moving the existing arrow function across as an argument with **no edits to its body**. Comments that live inside the callback travel with it. Comments that sit above the enclosing function stay above the enclosing function.

Do not touch anything else in these functions. The draft-prompt callback writes a response through Firebase from a button handler; leave that write exactly where it is — it moves in 09-03 as part of the writer split, and doing it here would mix two kinds of change in one diff.

Keep the wrapper file free of any comment naming an identifier from 09-01's UI or app-state denylists. 09-04's contract check deliberately does not strip comments — a false positive there is a minor annoyance, but the alternative is a false negative in exactly the bug class NET-01 exists to prevent. Describe roles, not names.

After the nine, confirm by direct grep that `index.html` retains raw listener calls only for the four room and lobby watchers this task did not touch plus the two one-shots — six in total.
