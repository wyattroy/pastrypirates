<objective>
Rewrite the bot ladder to run one brain, and capture the balance baseline **before** the pass
dubloon exists.

`scripts/bot_ladder4.js` is the only script in the repo that loads `4/`, and it currently seats its
control arm with `Game.prototype.planTurnClassic` — the method plan 05 deletes. So FIX-06 is two
pieces of work, not one (D-05): deleting the planner without rewriting the ladder breaks the ladder,
silently, until someone next tries to tune a bot.

Purpose: this plan also produces the *before* half of D-07's balance gate. The comparison axis is
**time**, not seat — `planTurn` already dispatches unconditionally to the race planner, so once the
classic planner is gone there is no second brain to seat against. That makes the ordering
non-negotiable: the baseline must be measured on a tree where passing does not yet pay, which means
this plan lands before RULE-01, not after.

Output: a one-brain ladder that reports pass rate and voyage length derived from the event stream the
engine already records, plus a committed baseline artifact plan 06 diffs against.
</objective>

<sequencing_note>
**Why this plan runs in wave 2 and RULE-01 waits for wave 3.**

D-07 needs the same statistic measured on identical seeds either side of the pass dubloon. The
rewritten ladder must therefore exist *before* RULE-01 lands, and it must not depend on anything
RULE-01 introduces.

It does not: the pass and turn entries the rate is derived from are already in the event stream
today, and the rewrite's only relationship to plan 05's deletion is that it stops naming the deleted
method. Plan 05's deletion is behaviour-neutral for the ladder — `planTurn` already dispatches to the
race planner unconditionally — so the deletion can land after the baseline without invalidating it.

The three-way ordering, stated once: **rewrite and measure (this plan) → pay the dubloon (plan 04) →
delete the dead planner (plan 05) → measure again and ask (plan 06).**
</sequencing_note>
