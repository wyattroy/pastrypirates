**`src/main.js`** — the module entry. Import both constants from `./module-contract.js` using that exact specifier, with the `.js` extension written explicitly; browser ESM performs no extension resolution, and an extensionless specifier would resolve under Node while 404-ing in the browser.

Set the browser marker by indexing `window` with the imported `MODULE_OK_FLAG` rather than writing the property name as a literal. This makes the leaf import load-bearing: if module resolution silently failed, the marker could not be set at all. Guard that assignment behind `typeof window !== "undefined"` (D-15 as amended). Add the D-17 tripwire inside the same browser-only branch: when `firebase` is not a defined global, emit a `console.error` naming `src/main.js` and stating that the classic script load order may be broken. Test it with `typeof`, never with a truthiness check on a bare identifier — `typeof` is the one operator safe on undeclared identifiers, and a truthiness check would throw under exactly the conditions the tripwire is meant to report. Scoping it to the browser branch keeps the Node import proof clean: under Node there is no script ordering to regress, so the tripwire has nothing to say (see the assumptions block above).

Beyond setting the marker and evaluating the tripwire, `src/main.js` does nothing. It must not call `boot()`, must not read or write game state, and must not alter initialization timing in any way (D-18).

Write the contract down so the next person does not have to rediscover it.

Create `docs/MODULES.md` covering, at minimum, these six subjects (D-22, FOUND-05):

**An HTTP server is required.** The canonical local server is `python3 -m http.server 8000`, chosen because it ships with macOS and needs no install (D-19). Note the `npm start` alias as a convenience and be explicit that the no-dependency path is the python3 one, so a reader without npm is not blocked.

**`file://` is unsupported, and why.** Module scripts require an HTTP origin; opening the page from the filesystem yields an opaque origin and the module entry will not load. Record that this is a deliberate exclusion listed in REQUIREMENTS.md's Out of Scope table, not an unimplemented feature, so nobody files it as a bug or tries to "fix" it.

**`.js` MIME expectations.** State the two measured values: `python3 -m http.server` returns `text/javascript`, and this project's live production host returns `application/javascript; charset=utf-8`. Both are valid JavaScript MIME types accepted by module scripts in every evergreen browser, and neither environment needs any configuration. State that plainly — do not describe a setup step that does not exist. Add the failure mode a reader actually needs: a host that returns a non-JavaScript type such as plain text or a generic binary type causes the browser to refuse the module, and Safari does so more silently than Chromium, which is what makes the page-load tripwires worth having.

**The classic-before-module load-order rule.** Module scripts are always deferred; non-deferred classic scripts execute synchronously as the parser reaches them. The Firebase compat tags at `index.html:25-26` must stay classic and stay ahead of the module entry, which is what guarantees `firebase` exists as a global before any module code runs. Note the standing tripwire in `src/main.js` that reports a violation at page load, and that `window.__pp_module_ok` is the machine-checkable marker confirming the module entry executed.

**The extraction hazard.** Any new script tag added to `index.html` must carry attributes. The Node harnesses locate the engine region by searching for an attribute-less script open tag, which currently matches exactly once; a second attribute-less occurrence silently redirects every extraction rather than failing loudly. Phrase this as a standing rule for Phases 8–11, since that is when new tags are most likely to appear.
