# v1.2 Milestone Audit

**Run after the milestone was archived**, at Wyatt's instruction — I had skipped it during
`/gsd-complete-milestone` on the judgement that per-phase verification was strong enough. **That
judgement was wrong in one respect**, and this audit is why: it surfaced real documentation debt and
one requirement whose closure was never propagated back to the phase that recorded it as open.

Nothing found here blocks the release. Everything found is worth fixing before it becomes archaeology.

No unsatisfied requirement. No integration gap. Both end-to-end flows complete. What remains is
bookkeeping that has drifted from reality.

### A caveat on how "satisfied" was reached

The workflow's status matrix wants three independent sources per requirement: VERIFICATION status,
SUMMARY frontmatter, and the traceability table. **Four of five phases declare no `requirements:`
field in SUMMARY frontmatter**, so strictly the matrix returns *partial — verify manually* for
CLOCK, STORM, AI, NARR and VERIFY.

They are recorded as satisfied on the other two sources plus direct evidence, which is a judgement
call and is flagged as one. It is a documentation shape problem, not a doubt about the software.

## Tech debt — what this audit actually found

**1. Phase 13's three open human-verification tests are now all closed — 2026-07-31.** Three
sessions, one each:

- the **localStorage version-guard blobs** — Check 1, run by Wyatt in Safari, then a **Check B
  re-run** after the original was found inconclusive by construction (it pointed at room `ABCD`,
  which does not exist, so a cleared blob was the correct result and the test could not fail);
- the **guest-initiated `#scPause`** and clicking **`#shotClockNum`** to resume — CLOCK-03's actual
  affordance — closed live in room `SGZZ`.

Evidence lives in `13-VERIFICATION.md`'s trailing closure sections; this audit points at it rather
than restating it. The earlier note stands as the contrast that made the guest path worth proving
separately: Wyatt had exercised pause/resume and timer-off from the **host**, and `timerOff` was
confirmed propagating to the guest, so the mechanism worked — but a host-driven pause is not evidence
for a guest-driven one. What closed it was the host's `broadcastClock` re-broadcast carrying
`paused=true` 116ms after the guest's click, which is the host applying the guest's pause rather than
the guest setting a local flag.

**Caveat on the arithmetic:** item **4** of that list (the solo pause/resume regression) was counted
among the two this audit treated as already closed, and it was **not** re-exercised in any of these
sessions.

**2. Phase 13's CLOCK-01 closure is now recorded in Phase 13's own file.** This audit appended the
`## CLOCK-01 CLOSED 2026-07-31 by Phase 17` section to `13-VERIFICATION.md`, which was the point of
the finding — evidence generated in a later phase had never flowed back to the phase that recorded
the gap, the single most useful thing this audit caught. **Residual:** the Observable Truths table
row 1 and the frontmatter `behavior_unverified_items` still carry their original ⚠️
`PRESENT_BEHAVIOR_UNVERIFIED` marker, deliberately, because that file is append-only by convention.
A reader who skims only the table still gets the old picture. That is the honest remainder of this
item, not its deletion.

**3. Phase 14's guest storm-push decision exists, but not where the phase can see it.** It is
recorded as STORM-02 in PROJECT.md, ROADMAP.md and STATE.md.

**4. The traceability table listed 10 delivered requirements as `Pending`.** Corrected by this audit.

**5. Structural artifacts.** Phase 16 has no PLAN.md (built directly overnight, recorded as such);
Phase 17 has no SUMMARY.md (a verification phase produces no plans); four phases declare no
requirements in SUMMARY frontmatter.

**6. NEW — pausing in the final ~1 second of a turn does not save the turn.** Wyatt paused from the
host with roughly one second left; the turn expired anyway, the "too slow" penalty was applied, and
play continued.

**Suspected** cause, from a code read and **not yet isolated with a test**: `togglePause` writes to
Firebase, and the host only applies the pause when `watchPause`'s callback fires on the round-trip,
while `shotClockTick` runs locally every 500ms and reaches the 30000ms expiry independently. So
there is a window at the end of a turn that a pause cannot beat. Worth an explicit decision: accept
it, or have the host apply the pause optimistically/locally before the round-trip completes.

**This is not a Phase 13 verification failure.** It was found while closing Phase 13's checks, and
those checks pass; it is filed here as its own finding under `phase: post-audit-findings` so nothing
implies otherwise.

_This tech-debt section was amended on 2026-07-31, after the Phase 13 checks closed — items 1, 2 and
6 post-date this audit's own `audited:` stamp._

## What I would not do

None of this justifies reopening v1.2. The software is shipped, live, and verified more directly
than the paperwork implies — two complete games, cross-browser, with measurements rather than
impressions. The debt is that the record under-describes what was actually checked, and in one place
over-describes what is still open.
