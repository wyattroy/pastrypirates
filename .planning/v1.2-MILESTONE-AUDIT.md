# v1.2 Milestone Audit

**Run after the milestone was archived**, at Wyatt's instruction — I had skipped it during
`/gsd-complete-milestone` on the judgement that per-phase verification was strong enough. **That
judgement was wrong in one respect**, and this audit is why: it surfaced real documentation debt and
one requirement whose closure was never propagated back to the phase that recorded it as open.

Nothing found here blocks the release. Everything found is worth fixing before it becomes archaeology.

bookkeeping that has drifted from reality.

### A caveat on how "satisfied" was reached

The workflow's status matrix wants three independent sources per requirement: VERIFICATION status,
SUMMARY frontmatter, and the traceability table. **Four of five phases declare no `requirements:`
field in SUMMARY frontmatter**, so strictly the matrix returns *partial — verify manually* for
CLOCK, STORM, AI, NARR and VERIFY.

They are recorded as satisfied on the other two sources plus direct evidence, which is a judgement
call and is flagged as one. It is a documentation shape problem, not a doubt about the software.

## Tech debt — what this audit actually found

**1. Phase 13 has three human-verification tests that were never closed.** The two-window game today
closed the CLOCK-01 one. Still open: the localStorage version-guard blobs (unversioned vs versioned
`pp_sess`/`pp_solo`), a **guest-initiated** `#scPause`, and clicking `#shotClockNum` to resume —
which is CLOCK-03's actual affordance. Wyatt exercised pause/resume and timer-off from the **host**
today, and `timerOff` was confirmed propagating to the guest, so the mechanism works; the
guest-initiated and click-to-resume specifics were not separately exercised.

**2. Phase 13's file still says CLOCK-01 is unverified.** It was closed by Phase 17. Evidence
generated in a later phase never flowed back to the phase that recorded the gap — the single most
useful thing this audit caught.

**3. Phase 14's guest storm-push decision exists, but not where the phase can see it.** It is
recorded as STORM-02 in PROJECT.md, ROADMAP.md and STATE.md.

**4. The traceability table listed 10 delivered requirements as `Pending`.** Corrected by this audit.

**5. Structural artifacts.** Phase 16 has no PLAN.md (built directly overnight, recorded as such);
Phase 17 has no SUMMARY.md (a verification phase produces no plans); four phases declare no
requirements in SUMMARY frontmatter.

## What I would not do

None of this justifies reopening v1.2. The software is shipped, live, and verified more directly
than the paperwork implies — two complete games, cross-browser, with measurements rather than
impressions. The debt is that the record under-describes what was actually checked, and in one place
over-describes what is still open.
