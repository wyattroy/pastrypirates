# W4-5 — done

## What a player sees

The "Tap and hold the sea to reveal the board" hint now sits **directly above the card it is about**,
and it breathes with the same pulse every other thing the game is asking of you uses.

| | hint → card gap, before | after | pulse |
|---|---|---|---|
| desktop 1200 | 295px | **6px** | none → **pp4Glow** |
| tablet 768 | 295px | **6px** | none → **pp4Glow** |
| phone 390 | 222px | **6px** | none → **pp4Glow** |

6px is not a number invented here — it is `AIR`, the gap every other stacked floater in `stage.js`
already leaves.

## The cause was NOT what the first fix assumed, and that is the lesson

The obvious reading is "the placement search prefers the wrong spot". So the first attempt added a
card-adjacent candidate at the front of that search, ran the gate green — **and moved the hint
exactly zero pixels.**

`peekHintLast()` returned early unless the prompt was the RADIAL bloom. With a card up, **the
placement search never ran at all.** The hint was not mis-placed; it was *un*-placed — sitting at
whatever position the last radial prompt had left it at. The preference change was correct and
unreachable.

**And the thing that misled the first attempt was a comment.** `peekHintTick`'s own header says it
shows the hint "inside whichever prompt box is up". That is intent, not runtime — rule 6, in the
exact shape the rulebook describes. The measurement is what caught it: the fix went in, the gate went
green, and the number did not move.

## Both changes

1. **`peekHintLast()` runs when a card is up as well as a radial fan**, and the condition is derived
   from what is on screen (a visible panel) rather than a list of prompt class names that would need
   editing every time a new prompt kind appears.
2. **A card-adjacent candidate is tried first** in the placement search, derived from the card's own
   rect.
3. **The hint is named in the ONE attention-vocabulary rule** the stage buttons read — not given its
   own `@keyframes`, because rule 8 is that one gesture has one definition.

## What was deliberately NOT changed — read the graveyard before touching this again

The hint used to be pinned at `band.bottom - 44`, and the 2026-08-21 gate caught it drawn straight
across "Stay put", across a trade's ✓, and over the second line of "Call Flaky Jack" — five judge
findings, one cause. It became a preference search where **every** candidate is tested for clear air
and the last resort is to hide rather than cover the answer.

**So this is a change of PREFERENCE, never a new fixed position.** The gate asserts that distinction
directly: it counts the writes to the hint's position and fails on a third one, because red-proofing
found that an unconditional `hint.style.top = …` inserted before the loop pins the hint and escapes
any check that only inspects the loop. Six defeats tried, six caught.
