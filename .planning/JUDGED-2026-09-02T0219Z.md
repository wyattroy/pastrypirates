## ⚠ AND THE CREW-PHONE GUEST — HIS OWN PLAYTEST SEAT — HAS NEVER BEEN A PHONE

Found by comparing two preserved screens element by element (rule 22's discipline applied to
pictures the trial made): `crew-phone-host-012-settled.png` reads **"Tap and hold the sea to reveal
the board"**; `crew-phone-guest-012-settled.png`, same leg, same run, reads **"Click and hold the
sea to reveal the board"**. The host image is 780×1300; the guest image is 390×664.

**Read in the code, not inferred from the pixels:**

- `src/ui/stage.js:547-551` — `holdVerb()` returns *"Tap and hold"* only when
  `matchMedia("(pointer: coarse)")` matches. So the difference is the DEVICE, not host vs guest.
- `scripts/playtest_gate.mjs:358` defines the leg as
  `{ W: 390, H: 664, mobile: true, dsf: 2, guestW: 390, guestH: 664 }`, and its own comment says
  *"Both seats phone-sized, because a crew game between two phones is what he and a friend play."*
- `scripts/playtest_gate.mjs:421-422` opens the **host** with `mobile: !!def.mobile, dsf: def.dsf || 1`.
- **`scripts/playtest_gate.mjs:429` opens the GUEST with neither.** It passes only
  `W, H, dbgPort, httpPort, serveRoot, profileDir`.
- `scripts/lib/cdp.mjs:34` defaults the missing ones: **`mobile = false, dsf = 1`** — and line 70
  only enables touch emulation `if (mobile)`.

**So the crew-phone guest is a 390×664 DESKTOP window at 1×, with a fine pointer and no touch.**
The size was set and the device was not.

**The comment three lines above the bug already says what this costs**, because the identical fault
was found and fixed on the solo phone leg and never swept to the guest — `scripts/lib/cdp.mjs:65-69`:

> *"Measured: the phone leg's screenshot came back reading 'Click and hold the sea' where a real
> phone says 'Tap and hold' (D-40). **A phone leg that does not emulate a phone tests the wrong
> game.**"*

**What it means for the release, stated at the size Wyatt can steer by:**

1. **Crew-on-a-phone is the square he actually playtests** — the leg's own comment says most of his
   35 findings came from it — **and one of its two seats has been a small desktop in every trial
   this project has ever run.** Anything the guest seat proved about tap targets, touch-only
   behaviour, or art at 2× device pixels, it did not prove.
2. **It is a one-line fix and it is NOT this watch's item** — one item per watch, and
   `playtest_gate.mjs` is being read right now by the trial at sea. Chart row written.
3. **It answers a question that has sat open in the record.** `docs/INTENDED-BEHAVIOUR.md:272`
   carries *"The hint 'Click and hold the sea to reveal the board' appeared on a guest and not on a
   host… Observed once, 2026-08-30. **Not measured**"*. It is now measured: **the instrument, not
   the game.** That row can be answered rather than re-wondered a fourth time.

**What would prove me wrong, named before the fix exists** (rule 6's working form): if the guest seat

## THE THIRD FAIL — THE GAME'S MONEY SYMBOL VANISHES ON THE WEBKIT LEG, AND ONLY WYATT CAN FINISH THIS ONE

`solo-tablet-wk-026-settled.png`, Day 14, the black-market ceremony. The card reads:

> 🏴 **The shelves be bare…**
> Sold-out islands fly the black market flag. They'll find ye one more ingredient — for **10⬜.**

**There is a blank where the coin should be, and then an orphaned full stop.** The judge caught it
independently: *"missing/blank currency icon after '10' leaves an awkward gap before the period."*

> ## ⚠ CORRECTED 2026-09-02T11:xxZ. EVERYTHING BELOW THIS LINE ABOUT A "RAW GLYPH" IS WRONG.
>
> **The game never draws 🌕 at all.** `src/shared/index.js:135` maps that character to
> `assets/icons/coin-emoji.png` and `emojify()` swaps it for an `<img>` before anything renders, so
> the typed character never reaches the DOM. **What came back blank was that IMAGE, with its layout
> box intact** — the gap is 42 px and the coin that renders in the next run's same box is 42 px,
> with the full stop starting at the identical column. **WHY IT DID NOT PAINT IS NOT PROVEN**; what
> is proven is what it is not. Full account and the numbers:
> [`T005-2026-09-02-THE-COIN-AND-THE-RIG.md`](T005-2026-09-02-THE-COIN-AND-THE-RIG.md).
>
> **And this page had the disproof in front of it:** the 🏴 it quotes two lines up is a bare
> U+1F3F4, which `EMOJI_IMG` does NOT map, so it is a typed emoji the font drew — on this card, in
> this frame, in this WebKit capture. A rig with no emoji font would have blanked it too.
>
> **So the question this page put to Wyatt — does real Safari blank the typed 🌕 — is VOID, not
> unanswered**, and the "two representations of one coin" reading is wrong: there is one
> representation and it is already the image everywhere.
>
> **How it went wrong, because it is worth more than the finding:** this page read the SOURCE STRING
> and stopped. `panel.js:1155` really does contain a typed 🌕 — a true fact about the file that says
> nothing about the screen. **A source string is not a rendered string.**

**Traced to the source, in one line:** `src/ui/panel.js:1155` writes
``for <b>${bmPrice}🌕.</b>`` — a **raw U+1F315 FULL MOON emoji**, not an image. The coins in the
CAPTAINS panel of the very same screenshot render perfectly, because those are `<img>` elements
(`assets/icons/coin-emoji.png`). **Two representations of one coin, and one of them can disappear.**

**What is measured and what is NOT, kept apart:**
- **Measured, and the second half of this landed during the spot-check above:** on this WebKit build
  🌕 renders blank while other emoji on the same card do not — the 🏴 black flag two lines above it
  renders fine. **And the SAME card on Chromium renders the coin correctly** —
  `crew-desktop-host-020-settled.png` shows *"for 10🪙."* with the coin present, same build stamp
  `2026.09.01.7`. So it is one missing glyph on one engine: not a missing emoji font, not a
  slow-loading image, and not a code fault.
- **NOT measured, and it is the whole question:** whether real Safari on Wyatt's iPhone and Mac does
  the same. Apple ships a full emoji font, so it probably does not — **but Playwright's WebKit is
  not Safari, and this project's own rule is that no report may say "Safari passed" on its strength.**

**Why it is worth his ten seconds rather than a shrug.** 🌕 is the game's money symbol and it is a
raw emoji in dozens of strings, including several on the **How to Play** page (`index.html:2835-2847`
— crate prices, the black market, the call bounty, Muse). If any Safari renders it blank, the
currency disappears from the page that explains the currency.

**The durable fix is rule 23's, not a patch:** one representation of a coin — the image the game
already has — everywhere, rather than an emoji in some strings and an `<img>` in others. That is a
sweep, not a one-liner, so it is filed and not attempted here.

**Asked of him in BLOCKED ON WYATT**, because his phone is the only real Safari this project has.
