## ⭐ A design rule he stated, which is bigger than any one bug

> **"Everything in the narration box should appear from top to bottom, in that order. Remember this
> intent."** — Wyatt, 2026-08-01

**This is a standing rule, not a bug report.** The box reveals its contents in reading order: whatever
sits highest appears first, then the next thing down, and so on. It explains three separate findings
below (**P1**, **P4**), and it should govern anything added to that box in future rather than being
re-derived each time.

Concretely, top to bottom: **back button → message text → helper text → action buttons.**

---

## Fixes

### P1 — Italic helper text appears immediately, before everything
**Phase 18 · FIX-03 regression.** The smaller italicised helper line under a prompt is painted at
once, ahead of the message it explains. Wyatt: *"it should honestly appear with the buttons."*
Per the top-to-bottom rule it belongs **after** the message and **with** the buttons — 18-01 gated
the buttons on reveal-completion but never took the helper text with them.

### P2 — The line "flashes" before it starts fading
**Phase 18 · FIX-16, partial.** Fading in place now works (the jump is gone). But at the moment the
fade begins the text **vanishes completely and reappears at full opacity**, then fades from there.
Reads as a flicker. Likely the ghost element being swapped in: the live node is removed and the
clone painted a frame later, so there is one blank frame between them.

### P3 — Two-line messages still clip, inconsistently
**Phase 18 · FIX-16, NOT fixed.** The second line is cut off **while typing**, but only sometimes.
Stranger still: **the box sometimes corrects itself during fade-out** — so the height it should have
had is reachable, just not at the right moment. The intermittency is the important clue; it points
at a race between the reveal and the measurement rather than a wrong measurement. Screenshots in the
2026-08-01 message.

### P4 — Back button must appear FIRST
**Phase 18 · new, from the top-to-bottom rule.** The `‹` back button sits at the top of the box, so
it must be revealed **before** the message types in — not after. Currently it comes later.

### P5 — Action button still clipped at narrow widths
**Phase 18 · FIX-10, NOT fixed.** At 331px the prompt is still cut off. Screenshot shows the message
overflowing the box's bottom edge with the buttons sliced. **This was the highest-severity item in
the phase** — it can leave a player unable to take a legal action.

### P6 — Mute button can go off-screen on narrow screens *(new bug)*
**Phase 21.** The mute control sits right of the turn clock; on a narrow screen that row overflows
and the button leaves the viewport. **Wyatt's fix, decided:** on narrow screens **move the mute
button below the captains box.** Not a shrink — a relocation.

### P7 — Orphaned bracket after a resize
**Phase 18 · FIX-21, partial.** `(−1🌕)` splits across lines — but **only when the window is resized
after the text has typed in**. Types correctly at a fixed width. So the `nobrk` wrapper is applied,
and something re-renders the line without it on resize, or the reflow re-measures against stale
markup.

### P8 — Timer toggle state is not saved
**Phase 21 · half-pass.** Turning the timer off in solo works — but **refreshing the page turns it
back on**. The preference must persist across a reload, like the other saved session state.

### P9 — Credits should say "you hear", not "ye hear"
**Phase 21 · copy.** Wyatt: *"none of the credits are in-game"* — the Credits modal speaks to the
reader as a person, not to a pirate. Pirate voice stops at the game's edge.

### P10 — Name modal's X starts the game instead of going home
**Phase 22 · half-pass.** The modal appears in the right place in the flow, but its **close button
advances into the game** rather than returning to the home screen. A close control must cancel, not
proceed.

### P11 — About page's "Play Pastry Pirates" button still uses the old orange
**Phase 22 · FIX-06 gap.** The restyle covered the 12 enumerated `button.primary` sites; the About
page was built in a different workstream and its call-to-action kept the old solid-orange treatment.

### P12 — "Buy me a cookie" buttons are taller than their neighbours
**Phase 22 / KOFI.** In the footer row the Ko-Fi button is visibly taller than How to play / Credits
/ Captain's log / Feedback / About / Leave game. Make it match. Likely the Ko-Fi embed's own padding
or line-height leaking through.
