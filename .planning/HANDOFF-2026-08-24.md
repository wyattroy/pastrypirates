## Hard-won this session (beyond what the commit messages carry)

- **The hostgone trap:** `armHostGone()` arms a server-side onDisconnect that fires on ANY host
  disconnect, including a plain reload. Any future feature touching room `status` must ask: what
  does the RESUME path do when it finds this status? The host's own session blob (`pp4_sess`)
  re-enters resume on every reload — a status the resume path refuses is a permanent lockout.
- **The escape hatch stands down only after 3 consecutive healthy ticks** (`armResumeEscapeHatch`,
  orchestrator.js). Its first version disarmed on one lucky tick and missed a stall starting at
  t+2s — the red-proof caught it. Don't "simplify" that counter away.
- **`pendingStage` vs `pendingReveal` (panel.js) are two different questions** — "has the board
  settled" (gates the box) vs "may the player act" (gates the buttons). Re-merging them recreates
  the invisible-reveal lag.
- **THE ATTENTION VOCABULARY (supersedes the earlier "one pulse" ruling):** every attention
  animation is assigned in ONE block at the end of 4/index.html's stylesheet — pp4Glow (stage:
  coin, ceremonies, battle, Start buttons) and pp4Grow/pp4GrowSoft (board: fan petals, stay
  confirm, card rows). NEVER put var() inside keyframes (WebKit resolves it once at animation
  start — build 24d's swell was intermittent in Safari because of exactly this); the fan's layout
  reserves the swell's room via --pp4GrowPeak → SEP in stage.js; Reduce Motion swaps grow for the
  still glow, never for nothing. sailBounce belongs to sail squares alone ("don't touch the sail
  squares").
- **The menu is one list, two mounts** (`#footerRow.pp4MenuList` → phone ☰ sheet, desktop
  `#pp4Col`). Style it once; never fork per device.
- **Cloud rig:** `4/scripts/mp_rig.mjs` is the two-window crew rig and it works in this container
