## 1. THE HEADLINE: the pulse bug is dead

**Eight days of "the action buttons sometimes don't swell" is fixed and confirmed green by Wyatt on
his own iPhone.** The full account is in `.planning/debug-pulse/` (both ledgers are closed with a
SOLVED banner). The short version, because it changes how the next hard bug should be worked:

- **It was never a frozen animation.** The beacon on his phone printed
  `Trade:none(pp4Grow/running)` — the stylesheet grants the animation, the computed play-state
  reads `running`, and `getAnimations()` returns NOTHING. **The animation was never created.**
- **The trigger is SAILING.** `#actionPanel.pendingReveal` holds buttons at `visibility:hidden`
  until the typewriter AND `stageSettled()` (camera tween + ship glide) both resolve. Stay put and
  that wait is ~0; sail and the button is declared-but-not-drawn for up to 1400ms, and iOS 18.7
  WebKit never starts an animation granted to an element that was not being drawn.
- **The fix** (build `2026-08-25a`): every attention rule now says `#actionPanel:not(.pendingReveal)`
  — the swell is granted at REVEAL, never at build. **It was written as a stopgap; Wyatt APPROVED
  it as the design on 2026-08-25 (D-57, §2). It is permanent. Only the code comment is now wrong.**

### What this cost, and the lesson that is now in `docs/HARD-WON-LESSONS.md`

Three engines were driven at this bug and **all three were innocent, honestly and repeatably** —
WebKitGTK 2.52, WebKit 26.5 across twelve isolated birth conditions, and WebKit 26.5 playing real
voyages. Every one of those greens was true and **none of them was evidence**: the faulty engine
exists only on his phone. Two lessons were written up, both his:

1. **The user's device can be the only instrument** — name the engine in the sentence where you
   report a negative, or the reader hears "not reproducible" and stops.
2. **Widen the scope to what happened JUST BEFORE.** Every hypothesis for a week looked inside the
   dead prompt. The cause was an action taken two seconds earlier. **Ask him for the toggle before
   building another probe** — he produced *"if i stay put instead of sail, the pass/trade buttons
   DO swell"* in thirty seconds, and that is what cracked it.

## 4. The instruments, and how to use them

Playwright is **deliberately not a repo dependency** (no build step, no `node_modules`). Install it
anywhere and point `PW_DIR` at it:

```bash
mkdir -p /tmp/pw && cd /tmp/pw && npm init -y && npm i playwright && npx playwright install webkit
```

| Script | What it answers |
|---|---|
| `4/scripts/lib/wk.mjs` | **A WebKit MOUNT for the existing driver.** Same handle shape `openChrome()` returns, so `makePlayer()` runs unchanged on both engines. ONE DRIVER, TWO MOUNTS — do not write a second driver. It mutes itself in the page (WebKit takes no `--mute-audio`; the first version played the game aloud on his machine). |
| `4/scripts/pulse_menu_probe.mjs` | Does the swell run, per prompt, in a real voyage? Keeps turn menus apart from every other prompt and refuses to call a run a result if nothing swung. |
| `4/scripts/bubble_side_probe.mjs` | **Wyatt's reproduction of the side flip.** Sails NORTH, then frames the boat against a distant one so the camera pushes it to the screen's top edge — the only place a bubble is born BELOW. Read its header before trusting a zero. |
| `4/scripts/settle_order_probe.mjs` | What is drawn, and what MOVES, while the board is still moving. Its flip column has never gone red on its own — a zero there means "nothing broke", never "fixed". |
| `4/scripts/wk_birth_matrix.mjs` | Twelve birth conditions for a CSS animation in real WebKit. All twelve pass on 26.5 — kept as the record of what was ruled out. |
| `?debug=pulse` | The beacon, on any device. 🐛 chip → Copy log. It now reports **MISSING** (the CSS grants an animation and the engine never made one) distinctly from **none**, and counts MISSING on the chip. |

**Everything above must be run headless and muted, and killed before you reply (rule 17).**
