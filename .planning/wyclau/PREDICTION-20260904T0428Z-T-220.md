# PREDICTION — T-220, shallow-gear green exit

**His ruling** (DECISIONS.md, RULING-20260903T213014Z-t220-shallow-green): *"Let a depth you chose
come back green when its own checks pass — much nicer to use, and it removes a guard that has
caught a real failure once."*

**What I expect, before measuring:** `scripts/sea_trial.mjs`'s exit-code line
(`process.exit(verdict === "PASSED" ? 0 : 1)`) currently exits **1** for the `"NOTHING SAILED"`
verdict (a chosen gear with zero legs, e.g. `--gear=COSMETIC`) even when `npm test` passed and
nothing was skipped. Read of the surrounding code (lines ~394-440): `verdict` can only reach
`"NOTHING SAILED"` after `unitOk` is true, `gateOk !== false`, and `notRun.length === 0` — i.e. the
only way to get there is for every check that gear actually owes to have already passed. So exiting
1 there is not the guard doing its job; it is punishing a run for correctly promising nothing.

**WHY, so I can be checked:** the guard's real purpose (per the file's own comment at the exit line
and the CEO's earlier ruling) is to stop `INCOMPLETE` (a leg that was supposed to sail and didn't)
or `FAILED` (a check that failed) from reading as green. `NOTHING SAILED` is neither of those; it is
the correct verdict for a deliberately-shallow, fully-passing run.

**The fix I intend:** widen the exit condition to `verdict === "PASSED" || verdict === "NOTHING
SAILED"` on that one line. Nothing else about gear selection, the picker, or the `INCOMPLETE`/
`FAILED` paths changes.

**What would prove me wrong:** if `"NOTHING SAILED"` were reachable through some path where
`unitOk` is false, or `notRun.length` is nonzero, or a leg promised by the chosen gear silently
didn't run — i.e. if the verdict ternary chain (line ~394-398) doesn't actually gate it the way I
read it. I will re-read that ternary chain literally before touching the exit line, and I will
re-run the real trial once before and once after to confirm the exit code, not just the verdict
text.

**RED, measured before the fix:** ran `node scripts/qa/_redproof_t220.mjs` (spawns the real
`sea_trial.mjs --gear=COSMETIC --reason=...`, which really runs `npm test` as a subprocess — this
is why it is NOT wired into `npm test` itself, only run by hand for this one-time proof).
