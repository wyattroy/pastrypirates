## WHAT I HAVE NOT MEASURED, AND WHAT I EXPECT

**P1 — `--gear=FULL` / `--gear=PLUMBING` / `--gear=COSMETIC` / `--gear=NONE` are honoured at
runtime, and the report header names the forced gear.**
*Why:* `LEGS[gear]` has exactly those four keys and `REPORT`'s header interpolates `${gear}`.
*What would prove me wrong:* a run whose header says one gear and whose `legs:` line sails another.

**P2 — A gear value that is NOT one of those four keys silently sails the FULL fleet while the
report header prints the bad value.** `LEGS[gear] || LEGS.FULL` has no validation and no
normalisation, so `--gear=cosmetic` (lowercase — the exact spelling the Chart row itself uses in
its warning) is not the COSMETIC key. The *fleet* direction is fail-safe (more testing, per
`gear.mjs`'s own "a check that cannot see its subject must return the STRICT answer"), but the
*report* is not: it would say `gear **cosmetic**` over a ten-leg voyage.
*What would prove me wrong:* any uppercasing, validation, or `Object.keys(LEGS)` membership test I
missed on the path between `arg("gear")` and the header. If `--gear=cosmetic` either errors out or
prints `gear **FULL**`, this prediction is wrong.

**P3 — When the gear is forced, the report cannot say what the mechanical picker WOULD have said,
and cannot say WHY a person lowered it.** The picker is never run (`if (!gear)`), and there is no
`--reason` flag anywhere in the file.
*What would prove me wrong:* a `--reason`/`--because` argument I missed, or the forced `gearWhy`
containing anything derived rather than a constant string. `grep -c "reason" scripts/sea_trial.mjs`
> 0 would start to falsify it.

**P4 — `--gear=COSMETIC` exits NON-ZERO with the verdict `NOTHING SAILED`.** `legs.length` is 0, so
the verdict ladder falls to that word and `process.exit(verdict === "PASSED" ? 0 : 1)`.
*Why it matters:* his ask is literally *"a way to bypass"*, and a bypass that reports a red verdict
is a bypass nobody will use twice.
*What would prove me wrong:* an exit 0, or a verdict word other than `NOTHING SAILED`.

# THE RESULTS — written after measuring, 2026-09-03T18:0xZ

**P1 — RIGHT.** `--gear=FULL/PLUMBING/COSMETIC/NONE` were honoured and the header named the forced
gear. Nothing to correct.

**P2 — RIGHT, and worse than predicted in one respect.** I said an unknown gear would sail FULL
while the header printed the bad value. Measured on the recovered pre-change file
(`git show HEAD:scripts/sea_trial.mjs`, run with a 20s timeout and a scratch report path):
`--gear=cosmetic` → header `gear: cosmetic`, **10 legs queued, and it really began sailing**;
`--gear=SHALLOW` → identical. The falsifier I named (any uppercasing or membership test between
`arg("gear")` and the header) was checked by reading every one of the 16 lines matching `gear` —
there is none.

**P3 — RIGHT.** No `--reason` flag existed (`grep` returned nine hits, all prose), and the picker
was spawned only inside `if (!gear)`, so a forced gear erased the picker's verdict entirely.

**P4 — WRONG, AND THE WRONGNESS IS THE MOST VALUABLE THING IN THIS FILE.** I predicted
`--gear=COSMETIC` would exit non-zero with the verdict `NOTHING SAILED`. **It exited non-zero with
`INCOMPLETE — 10 leg(s) did NOT run`** — on a run that had correctly sailed the zero voyages that
gear asks for. `sea-trial-shots/report.json` is whatever the last FULL run left behind, and nothing
compared it against the fleet THIS run promised, so **every gear below FULL inherited the missing
legs as failures.** PLUMBING had it too: three promised, seven phantom.

**I only found this because I ran it.** My prediction reasoned correctly about the verdict ladder
and never once considered the stale file on disk — the exact "what happened immediately BEFORE?"
blind spot, where the cause is a previous run that had already finished. Fixed with one line
(`if (!legs.includes(leg.name)) continue;`); the same command now reads `0 of 0 · voyages that did
NOT run: none`.

**THE TRAP I NAMED — I DID walk into part of it.** I wrote that I wanted P2/P3 to be true because it
made a tidier item, and set the falsifier as a command rather than a feeling. That part held. What I
did NOT do is answer the falsifier in the last section of this file until a CEO asked for it — see
below.

**⛔ AND THE FALSIFIER BELOW WENT UNANSWERED UNTIL CEO 180 ASKED FOR IT — the single worst thing in
