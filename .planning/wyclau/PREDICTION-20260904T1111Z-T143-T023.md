**ROOT CAUSE, TRACED AFTER THE CEO FLAGGED IT:** `consumeEvent()` (`src/orchestrator.js:1602`)
drains newly-pushed events even after every seat is `done` (during the 2600ms flash before
`assignBadges()` runs — the comment at `SEED_AWARDS` line 79 already said as much: "something
downstream walks this stream while the voyage is running"), and unconditionally calls
`spawnPops(e, boardCell())` on each one. `spawnPops` (`src/ui/util.js:1947-1950`) reads
`e.state[i].pos` for whichever seats the event's narration names. Every event the real engine emits
carries a `state` snapshot for exactly this reason — `consumeEvent`'s own guest-mirror branch reads
`if(e.state)e.state.forEach(...)`. This instrument's fabricated events did not carry `state` at all,
so the moment the first one drained, `spawnPops` threw and the game's error boundary put up its
crash card — which then filled most of the phone viewport, hiding both the earlier real finding and
the fact that the picture no longer showed what the report claimed.

**FIXED IN THE INSTRUMENT ONLY** (`scripts/qa/t143_eov_phone_pose.mjs`, tooling, no game code):
every seeded `trade`/`battle`/`dock` event now carries a `state` snapshot of all four players
(`pos`/`coins`/`ing`/`done`/`baking`), matching the shape `consumeEvent` expects, plus the
ingredient/price fields those narration functions read (`gave`/`got`/`ing`/`price` — the real
engine always supplies them and the narration functions dereference them unconditionally).
Re-ran; console output is numerically identical to before (confirming the numbers were never the
problem), and **this time I opened both PNGs before writing anything below.**
