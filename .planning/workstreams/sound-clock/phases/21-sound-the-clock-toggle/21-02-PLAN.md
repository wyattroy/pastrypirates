`battle`, `battleflee` and `dodge` take `battle-swords` — D-01, and D-04 for fleeing and dodging,

deliberately suppressed in narration to avoid duplicate lines.

Declare two placeholder constants and export both, so the flag is mechanically checkable rather than
a comment nobody greps. `SHOTCLOCK_SOUND_PLACEHOLDER` holds the `battle-swords` stem, with a comment
recording that D-22 wants running out of time to make a noise so you notice even if you looked away,
that none of Luis's six is an alarm, that this one is short, percussive and unambiguously adverse,
and that it is a stand-in on the shopping list for Luis. `WIN_SOUND_PLACEHOLDER` holds the
`store-ingredient` stem, with a comment recording that D-05 wants the win screen to carry a sound

`EVENT_SOUND`'s `shotclock` and `shotclockskip` entries must reference the constant, never repeat
the stem string, so a later edit cannot quietly de-flag the placeholder by inlining it.

Write `soundForEvent(e)` as a PURE function — no `ctx`, no DOM, no side effect, safe to call under
Node. It returns `null`, or an object naming the stem and the bus to route it through. Its one
special case is the storm cue: when `e.t` is `newround` and `e.storm` is truthy, return the `storm`
stem on the storm bus. **This ordering matters and is the plan's single most important detail.**
`Game.ev()` at `src/engine/index.js:233` stamps `o.storm` onto every event it records, so during a
stormy round every single event carries `storm: true`. Keying the cue on `e.storm` alone would fire
the storm sound on every action of every captain for the whole round — the exact opposite of D-08.
Keying it on the pair is correct, and because `newround` is emitted exactly once per round
(`src/orchestrator.js:819` and `:845`), D-08's fires-once falls out of the pure lookup with no dedup
state at all. For every other `e.t`, return the `EVENT_SOUND` entry when it is a non-null stem, and
`null` otherwise — including for a key that is not in the table.

Add the storm bus: in `initAudio()`, create `stormGain` with its gain set to the exported
`STORM_VOLUME` constant and connect it to `masterGain`, so the storm sits quieter underneath the
short sounds (D-11) while mute and tab-blur still govern everything through the one master ramp.
Leave the short sounds uncapped — D-11 chose that deliberately.

Add `fadeStorm()` (D-09). It is a no-op when no storm node is in flight. Otherwise, on that node's
gain: `cancelScheduledValues(now)`, then `setValueAtTime(gain.value, now)` to anchor the ramp at the
CURRENT value rather than a stale target, then `linearRampToValueAtTime` to a small epsilon — never
to literal zero, which can throw or hitch in some engines — over `STORM_FADE_SEC`, then `stop()` the
source shortly after the ramp lands, and clear the held reference. Never stop the source without the
ramp: D-09 forbids a hard cut, and forbids the sound droning past the moment. Export
`STORM_FADE_SEC` as the tuning point.

Add `playForEvent(e)` — the impure dispatcher. First, when `e.t` is `newround` or `end`, call
`fadeStorm()`, because the arrival of the next round header or the end of the voyage is the exact
game-state signal that the storm moment has resolved. Then take `soundForEvent(e)`, return when it
is null, and otherwise `play()` the stem on the named bus; when it is the storm cue, hold the
returned node in a module-local variable so `fadeStorm()` can find it later. Two prohibitions: no
`appState.mySeat` or `isLocalTo` gate anywhere on this path, because D-07 wants the whole table
audible; and never write a field onto an event object to communicate with the audio layer. Any
mutation of an object `game.ev()` produced, or that `netPushEvent` carries, risks drifting the
determinism corpus that v1.3's engine fence exists to protect — all dedup and fade state lives in
this module's own local variables.

Add `playWinScreen()`, exported, which plays `WIN_SOUND_PLACEHOLDER` on the master bus. Note in its
comment that `end` and `finish` remain silent as *events* per D-06 — the win-screen cue is tied to
the screen appearing, not to the event.

Export `EVENT_SOUND`, `soundForEvent`, `playForEvent`, `playWinScreen`, `fadeStorm`, `STORM_VOLUME`,
`STORM_FADE_SEC`, `WIN_SOUND_PLACEHOLDER` and `SHOTCLOCK_SOUND_PLACEHOLDER` on the file's existing
trailing named export list.
