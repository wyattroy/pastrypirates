## Decisions Made

- Confirmed rather than assumed that `bot_storm_narration_test.js` needed no change — traced its two `windmove` references and found both only advance the event log to test `movedSinceTurnStart()`'s ordering behavior (BUG-2), never assert narration text.
- Confirmed rather than assumed that no `appState.logLines` consumer needed a new null-guard — walked all 4 real consumers (`util.js:1194`, `board.js:643`, `board.js:647`, `board.js:817`) and found every one already guards, because the `end` event (`txt:""`) already exercised the `describeFor()`-returns-`null` path before this plan touched anything.
- Reflowed the sidebet won/lost ternaries one branch per line rather than leaving the compact 2-line form. This was necessary to literally satisfy the plan's `grep -c 'nobrk' >= 13` acceptance criterion (a compact multi-branch ternary line packs 2 wraps into 1 grep-countable line, undercounting); the reformat changes no wording, sign, or amount — confirmed via `git diff -U0` inspection, which shows only the added span markup and line breaks.
- Because the sidebet reformat changed the ternary's on-line shape, `scripts/ui_contract_check.js`'s pre-existing D-29 pirate-register identifier allowlist (which excuses the `you` local-variable reads in this exact code, anchored on the old one-line shape) had to be re-anchored to the new shape — this is exactly the "reformat must re-anchor, not silently pass" behavior that check's own header documents, and it fired as designed rather than being a bug in this plan's work.
- `checkCoinParentheticalNobrk` anchors to 10 distinct sites, not literally "seven plus two" as the plan's prose framing suggested — the plan's count groups by outcome-clause differently (e.g. treating "each sidebet outcome clause" as multiple sites) than a single-function anchor would. The finer per-branch granularity was chosen so a regression naming exactly which branch lost its wrap is possible, rather than a coarser per-function anchor that could only say "somewhere in sidebet."
