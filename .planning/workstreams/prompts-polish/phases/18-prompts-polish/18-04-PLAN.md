<objective>
Stop telling a player they bribed their way out of giving up a crate when they had no crate to give
up. A loser with an empty hold and 5 or more coins should read the give-up framing; only a loser who
was actually offered the choice and took the coins should read the bribe framing.

Purpose: the current code uses "spoil is 5 or more coins" as a PROXY for "chose to bribe". That proxy
is wrong exactly when the hold is empty, which is common. The real signal exists only in
`src/orchestrator.js`, in the branch that presents the choice.

Output: an explicit `spoilChosen` boolean on the orchestrator's battle event, a real test replacing
the proxy, and an absent-field default that leaves every engine, replay and fixture event untouched.
</objective>

   the one-time re-record that v1.3 must stay clear of. `npm test` (which chains
   `determinism_baseline.js --verify`) MUST stay green.

   simulator and fixture event.** This plan therefore DEVIATES from RESEARCH's sketch: RESEARCH
   proposed `isBribe = spoilIng==null && spoilChosen===true`, which would flip every field-less event
   from the bribe framing to the new give-up framing. That is a text change to already-shipped
   history. Use a three-state derivation instead (below), which keeps field-less events byte-identical
   and applies the fix only where the real signal is present. Record this deviation in the SUMMARY.
3. **The two new strings are ruled copy, verbatim**: `Ye give up {spoil}.` for the loser-addressed
   rendering and `{loser} gives up {spoil}.` for the neutral/winner rendering. Do not reword them.
4. **The under-5-coins path is unchanged.** It still falls to the existing all-they-have line.
5. **Re-point assertions, never delete them** (copy-gate rule). The existing 5-coin assertion encodes
   the bug; it gets split, not removed.
