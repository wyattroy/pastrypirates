<objective>
Turn the tracer's raw last-frame-delta readout into an instrument whose numbers can be trusted, and
make it print a plain-English summary at the end of a voyage.

Purpose: this phase's entire deliverable is a number that Phase 20 then designs against. A
miscalibrated readout is worse than no readout — it would let a real stutter through as a pass, or
fail a build that was fine because a phone locked mid-run. `19-RESEARCH.md` names the three exact
ways this goes wrong (a Low Power Mode phone throttled to roughly 30fps read as constant stutter, a
historical 60fps rAF cap making a hardcoded target wrong in the other direction, and the animation
frame callback pausing entirely on backgrounding), and this plan defends against each one
explicitly.

Output: a calibrated meter, a throttled live readout, and an end-of-voyage summary written in
language Wyatt can act on.
</objective>

  <behavior>
    - `windMeterSample` given a delta above `WIND_METER_OUTLIER_MS` records it as a discarded pause and leaves the worst-moment slot untouched.
    - `windMeterSample` given the first `WIND_METER_BASELINE_SAMPLES` accepted deltas establishes a baseline equal to the median of those deltas, and does not change the baseline afterwards.
    - With a synthetic stream of 120 deltas at 33ms followed by one at 200ms, the baseline is 33, the worst is 200, and the summary flags a suspected Low Power Mode context.
    - With a synthetic stream of 120 deltas at 16ms followed by one at 900ms, the baseline is 16, the worst remains the largest accepted delta below the outlier bound, and the discarded count is 1.
    - The dip count increases only for accepted deltas greater than `baseline * WIND_METER_DIP_FACTOR`.
    - `windMeterReset` clears the frame reference without touching the histogram, the worst-moment slot, or the discarded count.
    - Sampling allocates nothing per frame: the histogram is a preallocated typed array and no object or array is created inside `windMeterSample`.
  </behavior>
  <action>
    Add the meter to the existing prototype region in `src/ui/board.js`, alongside the constants
    already there.

    **Constants.** `const WIND_METER_OUTLIER_MS=500, WIND_METER_HIST_MAX=100,
    WIND_METER_BASELINE_SAMPLES=120, WIND_METER_DIP_FACTOR=1.5, WIND_METER_LOWPOWER_MS=30;`

    **State.** A preallocated `const windHist=new Int32Array(WIND_METER_HIST_MAX+1);` plus
    `let windSamples=0, windBaselineMs=null, windWorstMs=0, windWorstAtMs=0, windDips=0,
    windDiscarded=0, windMeterStartMs=0;`

    **`export function windMeterSample(deltaMs, nowMs)`.** In order:
    1. If `deltaMs > WIND_METER_OUTLIER_MS`, increment `windDiscarded` and return without touching
       anything else. `19-RESEARCH.md` Pitfall 3: a single multi-second outlier alongside otherwise
       normal numbers is background time, not jank, and letting it into the worst-moment slot is the
       failure that would swamp the whole summary.
    2. Bucket it: `windHist[Math.min(WIND_METER_HIST_MAX, Math.round(deltaMs))]++` and increment
       `windSamples`. `Math.round` is half-up for positive values, and that is the stated rounding
       contract for every figure this meter reports. The final bucket is an inclusive overflow
       bucket for everything from 100ms up to the outlier bound.
    3. When `windSamples` reaches `WIND_METER_BASELINE_SAMPLES` and `windBaselineMs` is still null,
       set the baseline to the histogram's median. Never recompute it afterwards — a baseline that
       drifts with the load being measured cannot classify that load.
    4. Once a baseline exists, increment `windDips` when
       `deltaMs > windBaselineMs * WIND_METER_DIP_FACTOR`.
    5. Track the worst: when `deltaMs > windWorstMs`, store it and store
       `windWorstAtMs = nowMs - windMeterStartMs`.
    Allocate nothing inside this function.

    **`function windHistMedian()`.** Walk `windHist` from 0 upward, accumulating counts, and return
    the first index whose cumulative count reaches `Math.ceil(windSamples/2)`. Return `null` when
    `windSamples` is 0. State in the comment that this is the exact tie-breaking contract: the lower
    of the two middle values for an even sample count, which is the conservative direction for a
    smoothness figure.

    **`export function windMeterReset()`.** Clears only the frame reference (`windLastFrameMs=null`)
    — never the histogram, the worst-moment slot or the discarded count. Wire a
    `document.addEventListener("visibilitychange", ...)` inside the region that calls it whenever
    `document.visibilityState` becomes `"visible"`, and increments `windDiscarded` so the pause is
    counted rather than silently vanishing. `19-RESEARCH.md` Pitfall 3: the animation-frame callback
    stops entirely while the page is hidden, so the very next tick after a phone unlock reports a
    gap that was never a rendering problem.

    **Rewire `windDotLoop`.** Replace the tracer's inline delta handling with a single call to
    `windMeterSample(delta, now)`, set `windMeterStartMs` on the first frame, and keep the readout
    write throttled to `WIND_READOUT_MS`. The readout shows `Math.round(1000/deltaMs)` as a whole
    number of frames per second plus one plain word chosen against the measured baseline — `smooth`
    when the frame is at or under `windBaselineMs * WIND_METER_DIP_FACTOR`, `rough` when above.
    Before a baseline exists it shows the figure with the word `warming up`. `19-RESEARCH.md`
    Pitfall 4: the readout is the one thing that could contaminate its own measurement, so the text
    write stays throttled even though sampling happens every frame.
  </action>
