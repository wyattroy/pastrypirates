<objective>
Put the motion in the trade-wind channel: small specks that ride each arc through the stationary
arrows, spiral in at the end and vanish, so "into the whirlpool" becomes something you watch happen
rather than something the arrows merely imply.

Purpose: this is the second half of the moving rim, and the half with the real geometry problem.
The obvious shortcut — importing the sweep-path helpers that already animate a boat along the rim —
creates a module cycle the test suite hard-fails on, and the second obvious shortcut — assuming four
equal arcs of nine cells — silently breaks on the boards the engine actually generates. Both are
avoided by deriving the waypoint list at runtime from data the engine already exposes.

Output: `rimArcWaypoints`, `rimSpeckSpecs`, `rimSpeckFrame`, `buildRimSpecks`, the speck write inside
the existing shared loop, and guard assertions over all three pure halves.
</objective>

  <action>
Write the three pure halves in `src/ui/board.js`, inside the region markers so assertions 2 and 3 cover them, per D-08, D-22 and D-28.

**`rimArcWaypoints(rimCellInfo, q)`.** Filter the rim-cell list to the given quadrant and map each cell to its grid coordinate pair. Filtering preserves order, and the engine builds the list clockwise and contiguous by quadrant with the arc's head written last, so the result is already the correctly ordered waypoint list and already ends at the whirlpool. Do not sort, do not reverse, and do not assume a length. The engine randomizes arc boundaries with a three-cell minimum and records in its own comment that one arc occasionally spans nearly half the rim.

**Do not import the sweep helpers.** `src/ui/flow.js` already imports seven names from `src/ui/board.js`; importing back would close a cycle that `scripts/module_graph_check.js` detects with a depth-first back-edge scan and fails loudly on `npm test`. This is a verified structural constraint, not a style preference. A decorative speck also does not need what those helpers provide: the spline resampling exists to stop a boat visibly stair-stepping, and a small drifting speck reading as smooth motion between at least three waypoints on a near-circular rim is a far lower bar. Write a short local piecewise-linear interpolation instead and say so in a comment, naming the cycle as the reason so nobody "improves" it later.

**`rimSpeckSpecs(seed, count)`.** Mirror `windDotSpecs` exactly: clamp the count to zero through a new `RIM_SPECK_MAX` constant, create a private generator from the seed exclusive-ORed with the rim-flow salt introduced in plan 20-05, and draw a fixed, documented number of values per speck in a fixed order — an arc selector, a starting progress, a speed, a lateral offset across the channel's width, and a size. Derive the arc index from the arc-selector draw so the four arcs are populated roughly evenly rather than by chance. Document the draw order in a comment above the function, in the same words the dot version uses, because that comment is the only record of it.

**`rimSpeckFrame(spec, tMs, waypoints)`.** Compute the speck's progress along its arc from its starting progress plus elapsed time times its speed, wrapped into the unit interval so a speck that reaches the whirlpool reappears at the start of its arc rather than being removed and recreated mid-flight. Convert progress to a position by piecewise-linear interpolation between consecutive waypoints, then add the lateral offset perpendicular to the current segment so the specks spread across the channel's width instead of running down its exact centre line. Return the position, an opacity and a scale.

The opacity and the scale together are what makes "into the whirlpool" literal: both approach zero across the final fraction of the arc, set by a new `RIM_SPECK_VANISH_FRAC` constant, so a speck visibly shrinks and fades as it reaches the drop-off rather than simply disappearing.

**Use the shared fade curve.** Compute that fade by calling `windFadeEnvelope`, the helper extracted in plan 20-01 and used by the dots — not by writing a second easing curve here. This is the concrete mechanism behind D-28: the specks inherit the fade shape Wyatt approves for the dots because they call the same function, so a change he lands on moves both rather than leaving two copies to drift. Say that in a comment.

Return positions in grid coordinates, matching the waypoints' own space, and leave the conversion to layer percentages to the element writer in Task 3 — that keeps this half pure and testable with no notion of a board size.
