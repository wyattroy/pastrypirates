<objective>
Make each whirlpool turn, so it reads as the thing that stops the wind rather than a decal marking
where the channel ends. Four HTML elements over the board, each carrying a CSS rotation seeded from
the game seed into D-09's 8-to-12-second range, never pausing for weather, costing nothing per frame.

Purpose: WIND-03 had no prior art anywhere in this codebase, and the obvious implementation is the
wrong one twice over — animating the existing SVG image in place forces layout every single frame,
and reusing the dots' per-frame loop would spend JavaScript on something a constant-rate rotation
gets free from the compositor. This plan also builds the `#rimFlow` layer that plan 20-06's channel
specks ride in, so the layer's stacking and lifecycle are settled once by the cheaper of the two
features.

Output: `#rimFlow`, `ensureWhirlKeyframes`, `whirlDurationSec`, `buildWhirlpools`, `rimFlowTick`, the
un-doubled board draw, and a guard assertion over the seeded duration.
</objective>

Build the rim-flow layer and the four turning whirlpools, per D-09, D-10, D-22, D-23 and D-25. All new code goes INSIDE the region markers renamed in plan 20-01, so assertions 2 and 3 cover it.

**The layer.** Add `ensureRimFlowLayer()`, mirroring `windEnsureLayer`'s create-if-missing shape: a single `div` with id `rimFlow` appended to `#boardwrap`, absolutely positioned at inset zero, pointer-events none, aria-hidden, with the same border radius and overflow clipping the storm overlay already uses. Give its stacking an exported named constant `RIM_FLOW_Z` set to 2, and comment the two numbers it must stay below — the ripple host at 3 and the ships SVG at 4, both declared in `index.html`'s paint-order note. A whirlpool is board furniture: a ship must sail over it, exactly as it does today while the swirl is an SVG child of the board.

**The keyframes.** Add `ensureWhirlKeyframes()`, which returns immediately if an element with the id it creates already exists, and otherwise creates a `style` element, sets its text content to a single keyframes rule named `windWhirlSpin` that rotates from nothing to a full turn, and appends it to the document head. This is the only way to get a keyframes rule without touching `index.html`, because a keyframes block cannot be expressed as an inline style — an element's inline `animation` property can reference a rule by name, but the rule itself must live in a stylesheet. Do not add anything to `index.html`: another workstream is editing that file concurrently and assertion 4 of the guard enforces the boundary.

**The duration.** Add and export `whirlDurationSec(seed, idx)`. Create a private generator from the game seed exclusive-ORed with a new salt constant `RIM_FLOW_SEED_SALT`, distinct from both the rain's and the dots' salts so the three streams never correlate even though all three derive from one seed. Advance the generator `idx` times, then map the next draw into D-09's range using new constants `WHIRL_MIN_SEC` (8) and `WHIRL_MAX_SEC` (12). Both are values plan 20-07's tuning page puts under Wyatt's slider — D-09 locks a range, not a number, so the number is his — so declare them beside the other tunables with a comment saying so. Use the same seedless fallback the dots use when the seed is absent, so the decorative board does not throw.

**The whirlpools.** Add `buildWhirlpools(layer, seed)`. Read the distinct landing cells from `appState.game.rimHead` and the grid size from `appState.game.cfg.grid`. Store the joined set of head keys on the layer as a data attribute and rebuild only when it differs from what is already built — that makes the function idempotent across renders while still rebuilding correctly for a new game with a different rim layout. For each distinct head, create two nested `div`s: an outer one positioned and sized as a percentage of the layer, at the head cell's own grid box — left and top from the cell's coordinates over the grid size, width and height each one grid unit — and an inner one filling it, carrying the swirl art as a background image sized to contain, and carrying the rotation.

Percentages rather than pixels, deliberately: the layer spans the same box as the board, so a percentage position survives every resize with no recalculation and no resize listener, which is the same reason the active-turn ripple is positioned in container units.

Two nested elements rather than one, also deliberately: the outer element owns the position and the inner owns the transform, so the rotation animation is not competing with a centring translate on the same property.

Write the inner element's animation as the keyframes rule name, the duration from `whirlDurationSec`, a linear timing function and an infinite count. Do not write an animation play state at all — D-10 makes the rim a permanent feature of the board rather than this turn's weather, so there is no storm pause to wire up, and writing the property would invite a future change to pause it. When `prefers-reduced-motion` is set, skip writing the animation property entirely and leave the element otherwise identical: the whirlpool art must still be visible, held still. Phase 19 shipped a bug where reduced-motion players saw nothing rather than something held still, and it was silent and unlikely to be reported — do not repeat its shape.

**The tick.** Add and export `rimFlowTick()`, taking no arguments, which ensures the layer, ensures the keyframes and builds the whirlpools from the current game's seed. Call it from `render()`'s wind block beside the existing dot tick. The empty parameter list is the point: unlike the dots, the rim depends on neither the round's wind direction nor the weather, and a signature that cannot receive either is the cheapest way to keep D-10 true.

**Un-double the art.** In `drawBoard`'s rim loop, stop drawing the static swirl image at quadrant-head cells — draw the arrow at every non-head cell exactly as today, and draw nothing at the heads. Leave a comment naming the rotating HTML layer as the place the swirl now lives. If the static copy stayed, it would sit motionless underneath a turning copy and read as a doubled or ghosted image the whole time the rotation runs. The 36 arrow cells are untouched: D-08 keeps them static as signage, and the motion goes into the specks in plan 20-06.
