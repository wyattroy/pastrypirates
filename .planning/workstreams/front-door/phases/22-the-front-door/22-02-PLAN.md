## Decisions closed by this plan

| Question | Decision | Rationale |
|---|---|---|
| Ko-Fi on the About page: duplicated iframe embed, or a plain outbound link? | Duplicate the lazily-mounted iframe, with the `sandbox` attribute byte-identical to the in-game one, as a self-contained inline script | D-07 forbids sharing JS, and `mountKofi()` cannot be imported without dragging `appState` and the whole `src/ui/` dependency chain into a page that has none of the surrounding game markup. The embed markup is small and self-contained, so duplicating it honours Wyatt's recorded preference that the button opens the widget rather than navigating. **Fallback if the embed proves unworkable in a browser check:** a plain outbound link to ko-fi.com — record the switch explicitly rather than silently degrading. |
| Does `about.html` carry its own `robots` meta? | Yes — the same `index, follow, max-image-preview:large, max-snippet:-1` value | `max-image-preview` is a per-URL directive. The screenshot META-01 needs Google to promote lives on **this** page, so this page needs the permission. Omitting it would leave the phase's central asset ineligible for the large preview it exists to earn. |
| Does `about.html` carry its own `og:`/`twitter:` tags? | Yes, with About-page-specific title, description and canonical, but `og:image` stays the existing `og-image.jpg` artwork | Claude's discretion per CONTEXT.md. Open Graph drives chat-app link previews, not Google result thumbnails — RESEARCH.md is explicit that `og:image` was never META-01's lever. Keeping the shipped artwork there avoids a second asset swap in Plan 04 and avoids implying the screenshot is a social-card asset. |
| JSON-LD on `about.html`? | No | The shipped `VideoGame` block describes the game and already has a canonical URL on the homepage. Duplicating it would give the same entity two URLs. Not required by any decision record. |
| Where does the screenshot come from before Plan 04 runs? | The hero image points at the committed `og-image.jpg` (1200x663 — the exact target aspect ratio), with an adjacent greppable sign-off marker | The page must be fully renderable and verifiable before the human gates run. Using a real committed image at the target dimensions means the layout is verified against the real aspect ratio rather than against a grey box. Plan 04 swaps the `src`, `alt`, `width` and `height` and deletes the marker. |
