# Phase 22 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** the name modal (FIX-01, replacing the welcome-screen `#pname` field) and the new
`about.html` page (ABOUT-01/02, plus verifying the already-shipped META-01 markup survives).
**Not touched:** the game board, `.panel`/player-row styling, or anything under `#layout` — out of
this phase's boundary per `22-CONTEXT.md`.

## Design System

| Property | Value |
|----------|-------|

| Font | Body: `'Avenir Next', Avenir, 'Segoe UI', 'Trebuchet MS', sans-serif` (the `body` rule, `index.html:41`). `about.html`'s own stylesheet (D-07) must declare the **same font stack by eye** — it is a new file, not an extraction of the shared one. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, tight inline padding |
| sm | 8px | Button internal gaps, `.choiceRow`/`.footerRow` gaps |
| md | 16px | Default paragraph/section spacing on `about.html` |
| lg | 24px | `about.html` section breaks (Rules / Screenshot / Credits / Ko-Fi) |
| xl | 32px | `about.html` top-level block spacing on desktop |
| 2xl | 48px | `about.html` page top/bottom margin on desktop |
| 3xl | 64px | not used this phase |

Exceptions: **the name modal is verbatim reuse of the existing `.modalOverlay`/`.modalCard` shell
(`index.html:669–674`), whose padding is `26px 28px 22px`** — that is an established, shipped
pattern outside this phase's boundary to change; do not "fix" it to the 8-point scale as part of
this work. The 8-point scale above governs only new surface: the modal's *internal* content (label,
input, confirm control) and all of `about.html`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 13px | 700 (bold) | 1.4 |
| Heading | 17px | 700 (bold) | 1.25 |
| Display | 28px | 700 (bold) | 1.2 |

Matches the two weights already in use throughout `index.html` (`.nameLabel { font-weight:700 }`,
`.player-row .pname { font-weight:bold }`, plain body text at regular weight) — no new weight is
introduced. `Heading` (17px/700) matches `.modalStep h3` (`index.html:727`) and modal titles;
`Display` (28px/700) is new, for `about.html`'s single page-title only. The captain-name input
itself must stay **16px** regardless of the Label/Body tokens above — that is the existing
`.nameLabel input` rule (`index.html:711`) and exists specifically to stop iOS Safari's
auto-zoom-on-focus; do not shrink it to 13/14px.

## Implementation Notes (non-template, supplemental)

These aren't part of the template's checker dimensions but are load-bearing for the planner/executor
and were surfaced by reading the actual code, not asked of the user (already answered upstream):

1. **Both readers of `#pname` must change together when D-01 removes the field**: `requireName()`
   (`src/ui/lobby.js:92–97`, `($("pname").value||"").trim()...DEFAULT_NAMES[0]`) and the inline
   duplicate at `src/orchestrator.js:1113`. A missed second reader is the flagged failure mode.
2. **`pname` is an overloaded identifier** — the DOM id being removed vs. `pname()` the function in
   `src/ui/util.js` that renders a *seat's* display name (`pn()` → `pname()` → `escHtml`). Do not
   touch the function while removing the input.
3. **The modal must fit `showStep()`'s existing step machinery** (`stepChoose`/`stepHost`/`stepJoin`/
   `stepPassPlay`, `src/ui/lobby.js:89–91`) or deliberately sit outside it — this is a planning
   decision, not a visual one, but the visual contract above (same `.modalCard` shell) assumes it
   renders as a step-like sibling, not a nested second overlay.
4. **Screenshot reference dimensions**: the existing `og-image.jpg` (used for `og:image`/
   `twitter:image`/JSON-LD `image`, all already shipped per META-01) is **1200×663px**. Unless D-11's
   chosen frame dictates otherwise, the About-page screenshot should target the same aspect ratio
   (~1.81:1) so it is reusable as a direct crop/replacement for `og-image.jpg` later, though that
   swap is not itself in scope for this phase.
5. **`about.html` additions**: `sitemap.xml` currently lists only the homepage (D-05 adds an entry);
   `robots.txt` already `Allow: /` with only `lab.html` disallowed, so `about.html` needs no
   `robots.txt` change — just confirm it isn't accidentally caught by a future rule.
