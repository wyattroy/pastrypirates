## Decisions closed by this plan

| Question | Decision | Rationale |
|---|---|---|
| Which element and classes for the two About links? | An `<a>` (not a `<button>` — it navigates rather than opening a modal) carrying `class="footerBtn footerAbout"` in both places, with **no new CSS rule for `.footerAbout`** | The base `.footerBtn` rule already supplies `text-decoration:none`, `display:inline-block` and the teal border, so it renders correctly on an anchor with zero additions to the style block Phase 18 owns. The empty `.footerAbout` modifier follows the existing `.footerHow`/`.footerCredits`/`.footerKofi` naming convention and gives a later phase a hook without spending a CSS line now. |
| Why not the orange accent for these links? | Teal (the base `.footerBtn` treatment) | UI-SPEC's Color section reserves accent orange for one primary action per surface. The About links are navigation. |
| Why one task rather than two? | Both links are the same six-line change applied to two surfaces, and the META-01 close-out is a verification of markup this plan does not author | Splitting would produce two sub-10% tasks that only make sense together. |

## Why this plan is wave 2

`index.html` is a coordination point. Plan 01 edits its markup for the name modal in wave 1; this
plan edits the same file for the About links, so it cannot run in the same wave. It also needs
`about.html` to exist (Plan 02) before either link resolves. Note for the executor: **Phase 18
(`prompts-polish`) is concurrently editing `index.html`'s CSS block.** Expect concurrent edits to the
same file in a different region, and add nothing to the style block.
