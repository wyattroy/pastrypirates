# v1.3 — The Plan

**Ordered the way Wyatt asked on 2026-07-31: the fun, easy things first, the bugs last.**

Ten phases. Phases 1–5 are the enjoyable ones. Phases 6–10 are the grind.

> **One genuinely good side effect of this order.** Everything in Phases 1–5 only changes how the
> game *looks and sounds* — none of it touches the rules engine. That matters because changing the
> engine forces us to re-record 31 saved games that keep multiplayer in sync, and that's a slow,
> one-shot, careful job. Putting all the visual work first means **we don't go near that machinery
> until Phase 7**, and the fun phases can't break a multiplayer game. This ordering is safer than the
> one I proposed, not just more pleasant.

---

## Phase 1 — Prompts & Polish

**The idea:** the game stops feeling slightly off in the small moments.

| What changes | Why |
|---|---|
| Buttons wait for the sentence to finish typing | Right now the buttons appear while the text is still typing itself out, so the game asks you to decide before it's finished explaining |
| A narrow window stops cutting off the action button | **The worst bug in this list.** On a narrow window the button gets sliced in half by the edge of the box — and it's the only way to take that action, so a player can be locked out of a legal move |
| Orange buttons restyled | The 12 solid-orange buttons get the outline-and-tint look every other button already has |
| "{captain} is blown by the storm" removed | You watched the ship move. Saying it fires twice per storm, per captain |
| The bribe line stops lying | A player with an empty hold is told they "bribed their way out of giving away a crate" when they had no crate. Becomes *"they give up 5🌕"* |
| The win banner stops saying "baked a Mexican Chocolate Pots" | Only prints "a" when the name takes one. No recipes get renamed |
| Ingredients stop stacking in one column on a phone | On a narrow screen each captain's row becomes five icons tall |

**Watch out for:** the first two are the same piece of code and have to be done together. The box
measures its own height once and hides anything taller — fixing one without the other puts the bug
straight back.

**Roughly:** the biggest of the fun phases, but every item is small and independent.

## Phase 2 — Safari Check (a gate, not a build)

**The idea:** find out whether the new wind animation is safe *before* anyone spends real time on it.

**What you'll actually see:** the wind dots, drifting on the board on ordinary turns — real and
working, built with the same technique the finished version would use. **Deliberately untuned:**
density, speed, size and jitter are all first guesses, so expect it to look too busy or too sparse.
Nobody is judging the look in this phase.

**What is being measured** is whether Safari stays smooth through a full game with it running.

**Build the prototype with a dial for dot count.** Then the answer is not just "Safari survives" but
*"Safari survives up to about this many"* — a budget Phase 3 can design against, instead of a bare
pass/fail.

**This needs Wyatt on real Safari**, same setup as the v1.2 Phase 17 playtest. Chrome can be driven
automatically; the Safari verdict is the one that matters and it is his machine.

**Why it exists:** the original Safari near-crash was caused by exactly this kind of animated layer
over the board. The fix was to pre-bake the effect into a picture instead of drawing it live. The new
wind uses that same machinery — but where a storm is occasional, **this would run on every single
turn.** That's a genuinely different load, on the one part of the game with a history of breaking
Safari.

**Done when:** a full game plays smoothly in actual Safari with the effect running — and we know
roughly how many dots it can carry — or we know it doesn't, and Phase 3 gets rethought before any
tuning time goes into it. **If it passes, the prototype becomes Phase 3's starting point**, not
throwaway work.

**Roughly:** an afternoon. Cheap insurance against losing a week.

## Phase 3 — The Board Comes Alive

**The idea:** the sea stops looking like a still picture.

| What changes |
|---|
| Small dots drift and flutter across the board on every non-storm turn — none of the storm's darkening |
| The wind arrows flow along the rim into the whirlpool instead of sitting still |
| Each whirlpool rotates, so it reads as the thing that stops the wind |
| A ship approaching the rim gets a visual hint it's about to be swept away, and roughly where it'll come out |

**Depends on:** Phase 2 passing.

**Watch out for:** the last row is a separate ask from an earlier list — players get swept into the
trade winds today with no warning at all. It fits naturally here since it's the same part of the
screen.

**Also worth knowing:** the arrow and whirlpool pictures are the ones your watercolor restyle will
replace later. You've already ruled that the new versions keep the same size and shape, so the
animation tuning done here survives the repaint. Nothing gets tuned twice.

## Phase 4 — Sound & the Clock Toggle

**The idea:** Luis's sound effects — and the timer on/off switch finally works everywhere.

| What changes | Why |
|---|---|
| Sound effects play at the right moments | |
| A mute button, sitting to the right of the turn clock | |
| Luis credited in the Credits | |
| **Solo gets the timer on/off toggle** | It's hidden today. The clock itself is already there — the pause button was deliberately turned on for solo — but the on/off switch is hidden behind a solo check |
| **The toggle actually works in pass-and-play** | It's on screen there and **silently does nothing**. It's driven by a multiplayer connection pass-and-play never makes |

**Why the clock toggle moved here** *(Wyatt, 2026-07-31)*: two reasons, and both are good ones.
The mute button sits **directly beside** this toggle, so building them together means touching that
corner of the screen once instead of twice. And solo and pass-and-play are broken **for the same
underlying reason** — the switch is wired to a multiplayer mechanism neither of them has — so **one
local code path fixes both.** Splitting them across phases would mean writing that path twice.

**Still in Phase 6:** the red urgency animation, and the wider parity/testing work. Those don't
overlap with the mute button and don't need to come early.

## Phase 5 — The Front Door

**The idea:** stop losing people before they've played.

| What changes | Why |
|---|---|
| You pick your name in a pop-up *after* choosing how you want to play | Today the name box sits above the buttons and people don't see it. They end up as a captain they never chose |
| A proper About page — rules, a screenshot, credits, Buy Me a Coffee | |
| Google shows a big preview image for the site | |

**Watch out for:** the rules already exist in two places. The About page must share one of them or
deliberately copy it — a third version that drifts out of date is the thing to avoid.

**Also:** the About page's screenshot is the first real picture the site has ever had on it, which is
what finally gives Google something to show. That's why those two sit together.

**Your own to-do:** verifying the site in Google Search Console is your job, not code, and it's the
slowest-moving piece — Google can take weeks. **Worth starting now, well before this phase.**

# The bugs

Everything below is the grind. Ordered so the worst-blocking things come first.

## Phase 6 — Pass-and-Play & the Turn Clock

**The idea:** fix the things stopping real people from playing right now.

| What changes | Why |
|---|---|
| Pause and disable behave identically in all three modes | The switch itself was fixed in Phase 4; this is the sweep that confirms **no mode is a special case** — same controls, same behaviour, same place |
| At 5 seconds left, the clock's rings grow much larger and turn red, and stay that way | Your ruling: new players get *"totally messed up"* by the clock. The urgency has to be unmissable |
| The two shared intro screens stop forcing the device to be passed around | Confirmed safe — no fairness reason for it |
| Prompts name the player they're addressing | |
| An automated test covers pass-and-play at all | There is none today |

**Why this is first among the bugs:** everything here is confirmed, located in the code, and
affecting people who are trying to play the game today.

**Note:** the clock's off switch itself was already fixed in Phase 4 — see there. What remains here
is the urgency animation, the parity sweep, and the missing test coverage.

## Phase 7 — Investigation

**The idea:** find out what's actually wrong with the mysteries, before anyone tries to fix them.

Nothing ships. These are all things nobody could explain by reading the code:

- Ingredients apparently vanishing from a game
- A turn seemingly being skipped
- Whether multiplayer players can really trade ingredients, or whether it's just confusing
- Yellow squares drifting when the window is resized
- **The storm narration audit** — *"still docked"* immediately followed by *"a gale blows them off
  the dock"*, and a ship in open water told it was blown off a dock that wasn't there. Two captains
  hit this in one nine-round game, so it isn't rare
- **The anchor line** — a bot that pays to anchor reads as *"still docked"* instead of *"anchored
  safely"*. This might be a wording bug or it might mean bots are sheltering for free

**Done when:** each one has either a real cause or a documented "watched it, it's fine, closing."

**Important:** anything found to be in the rules engine is **not** fixed here. It queues for Phase 8,
so the expensive part gets paid once.

## Phase 8 — The Engine Fix & the Re-record

**The idea:** the one phase that touches the game's rules. Done once, carefully, with a gate.

| What changes |
|---|
| Two players can no longer be dealt the same recipe |
| Anything Phase 7 found to be an engine problem |
| The 31 saved games that keep multiplayer in sync are re-recorded — **exactly once** |

**Why it's isolated:** re-recording is a one-way door. Every engine change has to be batched into
this single phase or the cost gets paid repeatedly. This is the same discipline the last milestone
used.

**Gate:** the re-record needs your explicit go-ahead, with a report of what changed and why.

## Phase 9 — Words

**The idea:** the narration says the right things, in your words.

- A page listing every line the game can say, with a feedback box under each and a button that copies
  it all at once — so you can review copy in one sitting instead of in dribs
- **You write the copy batch** (you chose one session over trickling it in)
- The opening line, the solo winner's line, the docking rule explanation
- Timeout messages that appear in the log but not on screen
- "Parley" becomes "Trade", with the word worked back in elsewhere
- A library of pastry-themed wind descriptions
- The final-round announcement reaching guests — **today only the host sees it, so guests play their
  last turn not knowing it's their last**

**Depends on:** the review tool being built first, and your writing session.

# Two things worth knowing, not blocking

**The pass-and-play bugs are affecting people now.** The broken off-switch and the forced
device-passing are hitting real players today, and this ordering puts them sixth. That's a
legitimate call — they're not new, and they've been live for a while already. Just naming it plainly
so it's a choice rather than an accident.

**This is a big milestone.** Ten phases, larger than v1.2 was. Phases 1, 3, 4 and 5 don't depend on
each other and could be worked in parallel; Phases 6 through 8 have to run in order because the
re-record needs to know everything that belongs in it. If it starts to feel long, the natural cut is
after Phase 5 — ship the fun as v1.3 and make the bugs v1.4.
